Как устроены оба пути сегодня — `ARCHITECTURE.md`. Здесь только маршрут
миграции: что уже сделано, чем это оплачено, что осталось. Подробности
этапов 1–6 (аудит, перенос промптов, спайк, разбор сессий) сняты 01.09 —

## Маршрут

### Этап 7: что уже закрыто

Приёмка этапа — **результат нового пути доходит до базы и папки бренда**,
а не сравнение планов между путями. Сравнивать нечего, пока пути отдают
разные по типу результаты.

| Артефакт | Посадка | Внешняя проверка |
|---|---|---|
| План | `strategy.land` | `_fit`: слот, дата, занятый день |
| Текст | `editor.land` | `check_voice`, гейт: находка = отказ |
| Макет | `design.land` | `inspect` после сборки разметки |
| Сценарий | **нет**, остаётся в `tasks/{id}/` | — |

`bridge.harvest` зовёт посадку **при любом исходе**, включая таймаут.
Прогон `2026-08-31-plan-01` упёрся в потолок на Идеаторе, а готовый план
десять минут лежал на диске и был выброшен. Второй раз так не будет.

### Этап 7: что осталось

**Честный замер полной цепи.** До него большую оптимизацию workflow не
начинаем. Меряется новая задача без переиспользования артефактов, цепь
`researcher → strategist` (Идеатор из связки плана убран 31.08), по
транскрипту сессии и её папке `subagents/`, а не по ощущению:

| Этап | Время | Est. API cost | Cache read | Cache write | Output |
|---|---:|---:|---:|---:|---:|
| Researcher | | | | | |
| Strategist | | | | | |
| Director / сборка | | | | | |
| **Итого** | | | | | |

Главный вопрос замера — **оправдывает ли качество результата стоимость и
время независимых субагентов.** Не «как уменьшить число сообщений»: число
сообщений это следствие, и резать его само по себе значит подменить
вопрос. Сначала данные.

Попутно замер закрывает потолок в 1800 с: на трёх ролях он проверен
(`plan-06`, 1223 с), на цепи с посадкой — ещё нет.

Ещё не сделано: **внешняя проверка на пути моста для сценариев**, и
**расписание сводки на понедельник** (команда работает, автозапуска нет).

### Этап 8: что снимать

Старый слой снимается по одной роли за раз, стенд — приёмка на каждом
шаге. Порядок от простого к сложному: `research`, `strategy`, `editor`,
`reels`, `design`. Вне моста остаются `reply.py` (разговор, а не задача с
началом и концом), `unpack.py` и `refresh.py` (мастер с кнопками) и
`publisher.py` (не AI-роль вовсе и намеренно работает при пустом балансе).

Мёртвые ключи `MODEL_PUBLISHER`, `EFFORT_PUBLISHER`, `MODEL_IDEATOR`,
`EFFORT_IDEATOR` сняты досрочно 01.09 — у них не было потребителя.

## Граница конфигурации: кто управляет моделью

Решено 30.08. **Старый путь** — моделями распоряжается Python:
`config.py` держит `ANTHROPIC_MODEL`, `role_models`, `role_effort`,
`agent.ask` берёт модель через `cfg.model_for(role)`. **Новый путь** —
моделью и рантаймом распоряжается Claude Code, Python не передаёт
**ничего**: `clean_env()` это белый список из семи переменных, и ни
`ANTHROPIC_MODEL`, ни `MODEL_*` в него не входят.

Закреплено в `.claude/settings.json`: `claude-opus-5`, усилие `medium`.
Файл версионируется — модель нового пути перестала быть умолчанием CLI,
которое меняется между прогонами и не оставляет следа. Флаги
`--model`/`--effort` из `bridge.py` при этом **не** передаются: пин живёт
в конфигурации Claude Code, иначе решение отменяло бы само себя.

Это граница, а не недоделка. Как только Python начнёт назначать модель
субагенту, выбор рантайма окажется размазан между `config.py` и
`.claude/` — ровно как выбор workflow чуть не размазался между
`bots/router.py` и `.claude/CLAUDE.md`.

**Модель на роль на новом пути задать можно** — frontmatter субагента
принимает `model` и `effort`. Первая редакция этого раздела утверждала
обратное, и неверное успело разойтись по четырём файлам. Настройка есть,
просто её дом — конфигурация Claude Code, а не `config.py`. Проверять
такое надо по документации, а не по памяти.

Чего решение **не** разрешает: возвращать `agent.ask` ради моделей по
ролям. Дорогой новый путь лечится замером и сокращением workflow, а не
откатом оркестрации в Python.

## Чем оплачены правила

Пять прогонов до первого удавшегося. Ни одну из трёх поломок стенд
поймать не мог: все три про поведение Director внутри headless-процесса,
а не про код моста. Код отработал верно — отказ записан, стоимость снята,
задача не задвоилась.

| `plan-01` | failed | 81 с | 0.78 | лимит запросов, до работы не дошло |
| `plan-02` | failed | — | — | процесс убит снаружи, строка осталась `running` |

Сами правила живут там, где исполняются: оркестрация — в

Здесь их копий нет намеренно: копии в этом проекте уже разъезжались с
оригиналом и успели соврать про две роли.

## Два факта, выясненных замером

**Мост работает по подписке.** Разовый `claude` → `/login` кладёт учётные
данные в Keychain (`Claude Code-credentials`, не файл — на macOS проверять
надо именно его), подпроцесс берёт их сам, `ANTHROPIC_API_KEY` в его
окружении не нужен. Зависимости от баланса API у нового пути нет; оценка
стоимости в `bridge_runs` — API-эквивалент, а не списание.

**У каждого вызова двойной пол: около $0.11 и 5–7 секунд.** Ни то, ни
другое не зависит от сложности задачи, это цена холодного старта. Для
«собери план недели» незаметно, для реплики в чате это пауза, после
которой человек считает, что бот сломан. Отсюда правило: через мост идёт
оркестрация нескольких ролей, а «что сейчас в очереди» отвечается кодом
из SQLite, без AI вовсе.

Инструмент замера — `deploy/spike-bridge.py`, повторяется командой:

```bash
./.venv/bin/python deploy/spike-bridge.py --live
```

Мерить надо в чистом окружении. Скрипт, запущенный из сессии Claude Code,
отдаёт подпроцессу по наследству `CLAUDECODE=1`,
`CLAUDE_CODE_ENTRYPOINT`, `CLAUDE_CODE_MESSAGING_SOCKET` и ещё несколько.
Завод под `launchd` не получит ни одной. Замер в унаследованном окружении
измеряет собственную среду вместо целевой.
