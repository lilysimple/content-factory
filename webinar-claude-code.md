# Вебинар «Введение в Claude Code» — материалы ведущего

Час эфира плюс справочник, из которого этот час собирается. Сквозная
линия всего вебинара одна:

> **Claude Code это не про код. Это агент, у которого есть руки —
> файлы, папки, терминал, интернет.**

Всё остальное следует из этой фразы. Финальный кадр — папка бренда, где
лежит контент-завод: человек должен уйти с картинкой «куда я это ставлю».

**Все готовые к показу примеры — в части XIII.** Там лежит стенограмма
первой сессии дословно, `CLAUDE.md` до и после с ценой в токенах, три
файла агентов целиком, команды, `.mcp.json`, хук-скрипт, валидатор и
поминутный сценарий демо. В разделах выше — объяснения, в части XIII —
то, что копируется на экран.

## Часть II. Терминал

### `cd`, `ls`, `mkdir` — и `pwd`

Терминал это та же папка на компьютере, только вы в неё не кликаете, а
называете словами. Четыре команды покрывают 95% работы.

**`ls`** — *list*, «покажи, что здесь лежит». Открыть глаза.

```bash
ls
ls -la      # со скрытыми: .claude, .env, .gitignore — в проекте они главные
```

**`cd`** — *change directory*, «зайди в папку». Перемещение.

```bash
cd Documents        # внутрь
cd ..               # на уровень вверх
cd ~                # домой, в свою пользовательскую папку
cd ~/brand          # сразу по адресу
```

`~` это домашняя папка, `/Users/имя` на Mac. `..` всегда родитель.

**`mkdir`** — *make directory*, «заведи папку».

```bash
mkdir brand
mkdir -p brand/research/instagram    # сразу цепочку вложенных
```

**`pwd`** — *print working directory*, «где я сейчас». Новичок потеряется
в первые три минуты, и это его спасение.

```bash
pwd
```

### Как это выглядит целиком

Первые тридцать секунд работы, дословно:

```
$ pwd
/Users/lily

$ mkdir brand
$ cd brand
$ pwd
/Users/lily/brand

$ ls
                      ← пусто, и это нормально

$ mkdir -p research posts video design
$ ls
design    posts     research  video
```

Четыре папки — это уже скелет контент-завода: куда складывать факты,
куда готовые тексты, куда снятое, куда макеты. Дальше в этой же папке
запускается агент, и он видит ровно эти четыре слова.

### Два приёма, снимающих мучения с набором

- **Tab дописывает.** `cd Doc` + Tab → `cd Documents/`. Не надо печатать
  длинные имена и бояться опечатки.
- **Перетащите папку из Finder в окно терминала** — он вставит полный
  путь сам. Напечатали `cd `, перетащили, Enter. Зал выдыхает.

### Почему терминал, а не окошко

Вопрос «а нельзя без этой чёрной штуки» прозвучит обязательно, отвечайте
до него.

- **Папка = контекст.** Агент видит ровно ту папку, в которой запущен.
  Запустили в `~/brand` — он знает бренд и не видит ваши налоги. Это
  одновременно разграничение доступа и память проекта. В чат-окне такого
  «где я» просто нет.
- **У него те же руки, что у вас.** Всё, что вы можете сделать командой,
  он сделает сам: создать сто папок, переименовать двести файлов, склеить
  видео, запустить скрипт. Веб-чат умеет только говорить.
- **Переносимо.** Mac, сервер, чужая машина — одинаково.

Честная оговорка: окно с кнопками есть, это десктопное приложение Claude
Code. Но терминал понимать всё равно надо — внутри приложения происходит
ровно то же самое, и все инструкции в сети написаны на языке терминала.

### Как кидать фото, видео и файлы

**а) Перетащить в окно.** Вставится путь, дальше пишете просьбу рядом:

```
/Users/lily/Desktop/IMG_4471.mov сними отсюда кусок с 0:12 по 0:40
```

На части терминалов Mac перетаскивание работает **с зажатым Shift** —
проверьте заранее на своём.

**б) Значок `@` — встроенный поиск по файлам.** Пишете `@`, начинаете
набирать имя, Claude Code подсказывает и подставляет:

```
посмотри @research/sources.md и скажи, чего там не хватает
```

Самый быстрый способ и главный ежедневный приём. Показать обязательно.

**в) Картинка из буфера.** Скриншот → **Ctrl+V** (именно Ctrl, не Cmd,
даже на Mac) → картинка в запросе. Для скринов статистики, макетов,
«вот так должно выглядеть».

**г) Просто положить файл в папку проекта.** Скопировали видео в
`~/brand/video/` и говорите «возьми последний файл из video». Для
тяжёлого — видео, архивов, выгрузок — лучший путь: ничего никуда не
загружается, файл лежит у вас.

### Три живых запроса, которые стоит показать

Видео — перетащили файл, дописали просьбу:

```
/Users/lily/Desktop/IMG_4471.mov
посмотри, что на видео, и предложи три места, где можно резать
```

Скриншот статистики — Ctrl+V и одна строка:

```
[картинка] это охваты за неделю. Что просело и на что это похоже?
```

Свой файл через `@` — самый частый приём дня:

```
прочитай @research/sources.md и @posts/2026-09-10.md
и скажи, какие факты в посте ничем не подтверждены
```

Проговорить вслух: **файл не «отправляется» целиком.** Агент читает его
с диска, когда нужно, и столько, сколько нужно. Поэтому трёхгигабайтное
видео его не пугает.

## Часть III. Установка

Здесь теряется половина зала, поэтому медленно и с экрана.

1. Где терминал на Mac, где на Windows. Три команды выше — больше ничего.
2. Установка Claude Code, вход по подписке.
3. Первый запуск **в своей папке**, не в домашней:

```bash
mkdir ~/brand && cd ~/brand && claude
```

4. Первый диалог: «посмотри, что в этой папке». Папка пустая — и это
   хорошо: видно, что агент реально смотрит, а не выдумывает.

## Часть IV. Разрешения и режимы

### Снять главный страх

«Он что-то сотрёт» — возражение номер один, и его обычно пропускают.

- Агент спрашивает перед каждым действием. Показать живой запрос.
- Правило безопасности одной фразой: **дайте ему отдельную папку, а не
  весь компьютер.**
- Тормоз есть: Escape прерывает, `/undo` откатывает. Человек должен это
  увидеть своими глазами.

### Четыре режима

Переключаются **Shift+Tab**, по кругу. Текущий виден внизу.

| Режим | Что делает | Когда |
|---|---|---|
| **Обычный** | спрашивает перед каждым действием | учитесь, первые дни |
| **Планирование** | **ничего не трогает**, только изучает и предлагает план | большая задача, страшно |
| **Авто-правки** | правит файлы без вопросов, на опасное спрашивает | рутина в знакомой папке |
| **Без тормозов** | не спрашивает ни о чём | почти никогда |

### Зачем авто-режим

Дело не в лени. В обычном режиме вы жмёте «да» тридцать раз за задачу и
к пятнадцатому **перестаёте читать, что подтверждаете**. Подтверждение,
ставшее рефлексом, не защищает ни от чего. Авто-режим честнее: один раз
решили «в этой папке я ему доверяю» — и дальше смотрите на результат, а
не на череду одинаковых окошек.

### Рецепт включения

1. **Начните с планирования.** Shift+Tab до plan mode, дайте большую
   задачу. Он изучит папку и покажет план, не тронув ни одного файла.
   Читаете, правите, соглашаетесь.
2. **Убедитесь, что папка под git** и изменения зафиксированы. Это ваша
   кнопка «отменить всё».
3. **Только теперь Shift+Tab в авто-правки** и отпускаете.
4. **Смотрите на результат, а не на процесс.** `git diff` покажет, что
   изменилось, одним списком.

### Список разрешённого вместо «разрешить всё»

Команда `/permissions` открывает список, где вы один раз говорите:
чтение — всегда можно, `git status` — всегда можно, удаление — всегда
спрашивать. Живёт в `.claude/settings.json` проекта и переезжает вместе
с папкой:

```json
{
  "permissions": {
    "allow": ["Read", "Grep", "Glob", "Bash(git status:*)", "Bash(git diff:*)"],
    "ask":   ["Bash(git push:*)"],
    "deny":  ["Read(./.env)", "Bash(rm -rf:*)"]
  }
}
```

`deny` на `.env` — не паранойя: так ключи не попадут в контекст даже
случайно.

*Диалоги `/permissions`, `/hooks`, `/config` открываются в терминальной
версии; в десктопном приложении настройки в своём интерфейсе.*

### Про режим «без тормозов»

Флаг `--dangerously-skip-permissions` существует, зал узнает о нём из
интернета, поэтому расскажите сами и с рамкой. Он снимает **все**
подтверждения. Уместен только там, где не жалко всей папки: изолированный
проект, ничего личного рядом, всё под git. **Никогда в домашней папке,
никогда с доступом к рабочей почте и облаку.** Название флага выбрано не
для красоты.

## Часть V. `CLAUDE.md` — и как писать его, чтобы не жечь токены

Главный блок вебинара и главный раздел этого файла.

### Что это

Файл в корне проекта, который агент читает **сам, в начале каждой
сессии**, без вашей просьбы. Это устав конторы.

Живая демонстрация:

1. «Напиши файл `CLAUDE.md`: кто я, какой бренд, для кого пишу, каким
   голосом, чего не пишу никогда» — агент создаёт файл сам. Или `/init`,
   который осмотрит папку и напишет черновик.
2. Открыть файл и показать: это обычный текст, его правит человек.
3. Проверка, производящая впечатление: выйти, зайти заново, попросить
   пост. Голос на месте, ничего не объясняли второй раз.

### Главная мысль раздела

> **Всё, что лежит в `CLAUDE.md`, оплачивается контекстом на каждой
> сессии — даже когда не нужно.**

Файл на 400 строк это не «подробный». Это налог, который вы платите за
каждый запуск, включая «поправь опечатку». И он же вытесняет из контекста
то, ради чего вы пришли.

Отсюда всё остальное.

### Семь правил хорошего `CLAUDE.md`

**1. Только то, что верно всегда.**
Голос бренда, запреты, правила работы — да. Состояние дел, цифры,
«сейчас у нас 12 тем в работе» — нет.

**Самый повторяющийся баг любого такого файла: вшитая фраза о состоянии
переживает то состояние, которое описывала.** Кнопка полторы недели
отвечала «дизайнер не подключён» после того, как он был подключён. Про
`sources.md` в документации год было написано «не собран», когда в папке
лежал готовый список из девяти каналов.

Лечится подстановкой вопроса вместо ответа:

```markdown
Состояние базы сюда числами **не переписывать**. Спрашивай базу:

    ./.venv/bin/python -c "import sqlite3; c=sqlite3.connect('factory.db'); \
    print(c.execute('select status, count(*) from themes group by status').fetchall())"
```

**2. Указатель вместо содержимого.**
Не пересказывайте архитектуру — назовите файл, где она лежит. Таблица
«вопрос → файл» стоит двадцать токенов и заменяет двести строк:

```markdown
| Вопрос | Файл |
|---|---|
| Как устроено целиком | ARCHITECTURE.md |
| Почему подсистема сделана так | NOTES.md, по разделам |
| Что решено и не переоткрывается | spec/README.md |
```

И прямо написать: **`NOTES.md` не читается автоматически** — берёшься за
подсистему, открываешь её раздел. Так большой справочник стоит вам ноль
до момента, когда он действительно нужен.

**3. Не дублируйте то, что агент и так прочитает.**
Схема базы — в коде. Промпты ролей — в своих файлах. Тесты — в тестах.
Копия промпта в двух местах разъедется через неделю и начнёт врать.
**У поведения должен быть один дом.**

**4. Раздел «правила, которые легко нарушить».**
Самая окупаемая часть файла. Сюда идут неочевидные грабли, на которых
агент спотыкается второй раз:

```markdown
- **Потолок сообщения 4096 знаков, подписи под картинкой — 1024.**
- **Slug бренда не меняется никогда** — на нём завязаны пути к артефактам.
- **`git` ищет репозиторий вверх по дереву.** Папка без своего `.git`
  найдёт первый попавшийся выше, и `add -A` унесёт туда всё подряд.
```

Три строки здесь экономят час разбирательств.

**5. Порядок блоков не менять.**
Кэш промпта — это совпадение префикса. Начало контекста не изменилось —
оно не пересчитывается и стоит дешевле. Перетасовали разделы ради
красоты — заплатили за весь файл заново. Поэтому дописывайте **вниз**, а
не вставляйте в середину.

**6. Замеряйте, а не угадывайте.**
Команда `/context` показывает, чем забит контекст и сколько стоит ваш
`CLAUDE.md`. Ориентир для проекта: **100–150 строк**. Перевалило за
двести — ищите, что вынести в отдельный файл и заменить строчкой-ссылкой.

**7. Где файл лежит — тоже решение.**

| Где | Когда читается |
|---|---|
| `~/.claude/CLAUDE.md` | всегда, во всех проектах — ваши личные привычки |
| `корень проекта/CLAUDE.md` | всегда в этом проекте |
| `подпапка/CLAUDE.md` | когда агент работает в этой подпапке |
| `.claude/CLAUDE.md` | правила для оркестрации, а не для проекта целиком |

Файл ищется **вверх по дереву**. Из этого следует неочевидный приём:
если вы зовёте роль одним вызовом и ей контекст проекта не нужен,
**запускайте её вне папки проекта**. Замер из реального завода: вызов
роли внутри папки тащил 10 660 токенов устава Director, снаружи — 729.
Пятнадцатикратная разница на каждом вызове, и на глаз она невидима:
ответ приходит одинаковый.

Из той же серии: **`--tools ""`, а не `--allowedTools ""`.** Первый
снимает набор инструментов, второй только права — определения всё равно
едут в контекст. 11 080 токенов против 731 на каждом вызове.

### До и после — на одном бренде

Так пишет человек, который старался. 180 строк, читается каждую сессию:

```markdown
# Мой бренд

## О проекте
Я Лиля, я занимаюсь AI-трансформацией бизнеса и карьеры. Я веду
телеграм-канал, инстаграм и линкедин. В телеграме у меня сейчас
1240 подписчиков, в инстаграме 3100, в линкедине около 800.
За последний месяц канал вырос на 140 человек, лучший пост собрал
4200 просмотров, это был пост про то, как я собирала завод.

## Структура папок
- posts/ — здесь лежат посты
- research/ — здесь лежит ресёрч
- design/ — здесь лежат макеты
- video/ — здесь лежит видео

## Мои продукты
Вебинары, воркшопы, консультации. Вебинар стоит 3000 рублей, воркшоп
12000, консультация 25000 рублей за час...

## Голос бренда
Мой голос — это спокойный интеллект и живая теплота. Я пишу по делу,
без инфоцыганства. Я верю, что с AI нужно работать вместе, а не
бояться его. В моих текстах есть тонкий сухой юмор...
[дальше ещё три абзаца про философию бренда]

## Что я уже сделала
Первый пост опубликован 3 сентября. Дизайнер подключён 12 сентября.
Сейчас в работе 12 тем, из них 4 в черновиках...
```

Что здесь не так — по пунктам, и каждый пункт больно:

- **цифры подписчиков** протухнут через неделю, а агент будет писать
  «нас уже 1240» ещё месяц;
- **структура папок** дублирует то, что видно по `ls`, и разъедется с
  реальностью в первый же день;
- **цены** — коммерческие данные, которые едут в контекст каждой
  сессии, включая «поправь опечатку»;
- **«что я уже сделала»** — самый ядовитый раздел: он врёт с момента,
  когда написан;
- **философия голоса** на четыре абзаца не делает текст лучше, чем
  пять правил списком.

То же самое после чистки. 34 строки:

```markdown
# lily.space — устав проекта

Читается автоматически каждую сессию. Держать **коротким**: всё, что
здесь лежит, оплачивается на каждом запуске, даже на «поправь опечатку».

| Вопрос | Файл |
|---|---|
| Кто аудитория, чем торгуем, цены | core.md |
| Нормы площадок и потолки | platforms.md |
| Примеры живых текстов для калибровки | voice/ |
| Что уже опубликовано | posts/, смотри по датам |

## Голос
- Заход через свой опыт, не через «в современном мире».
- Без хайпа и обещаний «за 3 дня».
- Каждый текст кончается выводом, применимым сегодня.
- Самоирония уместна, пафос нет.
- Тонкий сухой юмор, не шутки ради шуток.

## Чего не делаем никогда
- Не публикуем без подтверждения человеком.
- Не выдумываем цифры: нет источника — пишем «уточнить факт».
- Ник в Instagram пишется только так: `lily_.space`, с подчёркиванием.
  `lily.space` без подчёркивания — это сайт, а не аккаунт.

## Правила, которые легко нарушить
- Подпись под картинкой — 1024 знака, сообщение — 4096.
- В Telegram Markdown не работает, только `<b>`, `<i>`, `<code>`, `<a>`.
- Голая скобка в прозе («охват < 1000») роняет отправку целиком.

## Состояние — спрашивать, а не помнить
Сколько тем в работе и что опубликовано — смотри в posts/ и в плане,
сюда числами **не переписывать**.
```

Цена вопроса, если замерить `/context`: первый файл — около **2 100
токенов** на каждый запуск, второй — около **420**. При двадцати
сессиях в неделю разница набегает за месяц в полтора миллиона токенов,
потраченных на пересказ того, что и так лежит в папке.

И главное — короткий файл **работает лучше**. В длинном правило про
подчёркивание в нике тонет между ценами и философией; в коротком оно
одно из трёх в разделе «никогда».

### Скелет, который можно отдать залу

```markdown
# Бренд «Название» — состояние проекта

Читается автоматически в начале каждой сессии. Держать актуальным
**и коротким**: всё, что здесь лежит, оплачивается на каждой сессии.

| Вопрос | Файл |
|---|---|
| Кто аудитория, чем торгуем | core.md |
| Нормы площадок | platforms.md |
| Голос и примеры | voice/ |

## Кто мы
Три строки. Не абзац.

## Голос
Пять правил списком. Не эссе о философии бренда.

## Чего не делаем никогда
Стоп-лист. Самый читаемый раздел файла.

## Правила, которые легко нарушить
- Подпись под картинкой — 1024 знака.
- Ник в Instagram пишется только так: lily_.space
- Публикация только после подтверждения человеком.

## Как проверить состояние
Не числами, а командой. См. выше.
```

### Чего в `CLAUDE.md` быть не должно

- дерева файлов проекта — агент посмотрит сам и увидит актуальное;
- пересказа того, что делает код;
- истории проекта и списка прошлых исправлений — это git;
- длинных примеров текстов — им место в отдельной папке, читаемой по
  надобности;
- вежливых просьб вида «пожалуйста, будь внимателен».

## Часть VI. Субагенты

### Развести три понятия

| | Что это | Где живёт |
|---|---|---|
| **`CLAUDE.md`** | правила проекта, читаются **всегда** | корень папки |
| **Субагент** | работник со своей инструкцией, зовётся **по надобности** | `.claude/agents/имя.md` |
| **Команда** (`/имя`) | заготовленная просьба, запускаете вы | `.claude/commands/имя.md` |

Устав конторы — сотрудник — кнопка.

### Зачем субагент

Две причины, обе денежные:

- **Чистая голова.** У субагента свой контекст. Ресёрчер прочитал двести
  постов конкурентов — мусор остаётся у него, а не забивает вашу беседу.
- **Узкая инструкция.** Редактор, знающий только про голос бренда, пишет
  лучше универсала, который держит в голове ещё планирование и вёрстку.

### Шаги

**Шаг 1. Команда `/agents`.** Мастер: создать нового → в проекте или для
всех проектов → описать словами. Claude напишет черновик сам.

**Шаг 2. Понять, что получилось.** Файл `.claude/agents/writer.md`:

```markdown
---
name: writer
description: Пишет готовый пост по теме из плана в голосе бренда.
  Вызывать на «напиши пост», «поправь текст», «адаптируй под Instagram».
tools: Read, Write, Grep, Glob
---

Ты редактор бренда. Сначала читаешь core.md и берёшь оттуда голос.

Правила:
- Заход через личный опыт, не через «в современном мире».
- Никакого хайпа и обещаний «за 3 дня».
- Каждый пост кончается практическим выводом, применимым сегодня.

Готовый текст кладёшь в posts/{дата}.md и возвращаешь одной строкой,
что сделал.
```

Разобрать на экране по частям — в этом весь секрет:

- **`name`** — как звать.
- **`description`** — *самое важное поле*. По нему Claude решает, звать
  ли его вообще. Пишите не «редактор текстов», а **когда именно звать**,
  с примерами фраз. Плохое описание = агент, которого никогда не зовут.
- **`tools`** — что разрешено. Редактору не нужен интернет и терминал.
  Урезать инструменты — это и безопасность, и скорость, и экономия:
  определения инструментов едут в контекст.
- **Тело файла** — задание живому человеку в первый рабочий день.

**Шаг 3. Позвать.**

```
позови writer, напиши пост про то, почему агент говорит не твоим голосом
```

Или просто попросить по-человечески: если `description` написан хорошо,
Claude позовёт сам.

**Шаг 4. Довести напильником.** Получился слишком бодрым — открываете
файл и правите строку. Это текст, не программа.

**Шаг 5. Завести команду под частую задачу.** `.claude/commands/post.md`:

```markdown
Напиши пост по теме $ARGUMENTS.
Сначала прочитай core.md, потом позови writer.
Верни превью и жди подтверждения, сам никуда не публикуй.
```

Теперь работает `/post про обложки для Reels`. Ради этого всё и делалось:
длинная просьба сжимается в одно слово.

### Зависимые по очереди, независимые разом

Когда агентов становится несколько, появляется правило, которое стоит
денег и минут: **зависимые вызовы идут по очереди, независимые — одним
ходом.** Стратегу нужен результат Ресёрчера — только последовательно.
Редактор и монтажёр берут разные темы — вместе, в одном ходу.

На «собери контент на неделю» разница видна сразу: последовательно это
сумма всех ролей, вместе — время самой долгой. Разница в минутах, и всё
это время человек сидит и ждёт.

### Правило, экономящее зрителям месяц

**Не заводите семь агентов сразу.** Заведите одного — того, чью работу
делаете чаще всего. Поживите с ним неделю. Второго заводите, когда
почувствуете, что первому мешает вторая профессия. Заводы, построенные
за вечер, разваливаются: автор не успел понять, где узкое место.

## Часть VII. GitHub

### Зачем это контентщику

Через страх потери, иначе звучит лишней обузой:

- **История.** Агент переписал `core.md` и стало хуже — откатываетесь на
  вчерашнюю версию одной командой.
- **Резервная копия.** Компьютер утонул в кофе — профиль бренда жив.
- **Перенос.** Другой компьютер, скачали папку, продолжили.
- **Страховка от агента.** Пока изменения зафиксированы, любой
  эксперимент обратим. Именно это позволяет разрешать агенту больше.

### Шаги

**Шаг 0. Проверить, что git есть.**

```bash
git --version
```

Не отвечает — система предложит доставить, соглашайтесь.

**Шаг 1. Завести репозиторий в папке бренда.**

```bash
cd ~/brand
git init
```

Появилась скрытая папка `.git` — это вся история.

**Шаг 2. Сказать, кто вы.** Один раз на компьютер:

```bash
git config --global user.name "Имя"
git config --global user.email "почта@example.com"
```

**Шаг 3. Решить, что наружу не идёт.** До первой отправки, не после:

```bash
printf '.env\n*.mp4\n.DS_Store\n' > .gitignore
```

Можно и нужно поручить агенту: «собери `.gitignore`, чтобы наружу не
уходили ключи, видео и служебный мусор». Правило вслух: **ключи и пароли
в репозиторий не кладут никогда**, даже в приватный.

**Шаг 4. Первый снимок.**

```bash
git add -A
git commit -m "Профиль бренда: первая версия"
```

**Шаг 5. Подключить GitHub** через официальную утилиту:

```bash
brew install gh
gh auth login
gh repo create brand --private --source=. --push
```

Последняя команда делает всё сразу: заводит **приватный** репозиторий,
привязывает папку и отправляет содержимое. Слово `--private` произнесите
отдельно и с нажимом: профиль бренда, тексты клиентов и статистика — не
публичные данные.

Если репозиторий уже создан руками:

```bash
git remote add origin https://github.com/имя/brand.git
git push -u origin main
```

**Шаг 6. Дальше — одна фраза агенту:**

```
зафиксируй изменения и отправь на GitHub
```

Он соберёт коммит с осмысленным описанием. Ваше дело — иногда просить.

### Три грабли

- **`git` ищет репозиторий вверх по дереву.** Папка бренда внутри другой
  папки с `.git` — и `add -A` утащит туда всё подряд. Проверка:
  `git rev-parse --show-toplevel` покажет, куда вы на самом деле пишете.
- **Приватный ≠ секретный.** Ключ, однажды попавший в историю, считается
  утёкшим даже после удаления файла. Потому `.gitignore` пишется первым.
- **Не заводите репозиторий в домашней папке.** `cd ~ && git init` — и
  вся ваша жизнь становится проектом.

## Часть VIII. MCP — как подключить внешние сервисы

### Что это

MCP это способ дать агенту руки **за пределами папки**: календарь, Drive,
база данных, Telegram, таск-трекер, аналитика. Каждый сервис — отдельный
сервер, который вы подключаете один раз, после чего у агента появляются
новые инструменты.

Разница на пальцах: без MCP вы копируете расписание из календаря в чат.
С MCP агент сам смотрит календарь и строит план недели вокруг ваших
эфиров.

### Как подключить

Одной командой из терминала:

```bash
claude mcp add <имя> -- <команда запуска сервера>
```

Пример с сервером, который ставится на лету:

```bash
claude mcp add filesystem -- npx -y @modelcontextprotocol/server-filesystem ~/brand
```

Сервер, который ходит по сети, подключается по адресу:

```bash
claude mcp add --transport http notion https://mcp.notion.com/mcp
```

Проверить и посмотреть:

```bash
claude mcp list          # что подключено
claude mcp get notion    # подробности одного
claude mcp remove notion # отключить
```

Внутри диалога команда `/mcp` показывает подключённое и запускает вход в
сервисы, которым нужна авторизация: откроется браузер, вы разрешаете
доступ, токен ложится к вам на компьютер.

### Три области видимости — и почему это важно

| Область | Флаг | Кто видит |
|---|---|---|
| локальная | по умолчанию | только вы, только в этом проекте |
| проектная | `-s project` | все, кто работает с этой папкой — файл `.mcp.json` |
| пользовательская | `-s user` | вы, во всех своих проектах |

Проектная область кладёт конфигурацию в `.mcp.json` в корне, и она
**едет в репозиторий вместе с папкой**. Удобно для команды, опасно для
секретов: ключи туда не пишут, их подставляют переменной окружения:

```json
{
  "mcpServers": {
    "analytics": {
      "command": "npx",
      "args": ["-y", "some-mcp-server"],
      "env": { "API_KEY": "${ANALYTICS_KEY}" }
    }
  }
}
```

### Что сказать про MCP на вебинаре

Одно предложение и один пример, без настройки. «Это уровень, который
открывается после того, как папка и роли устоялись». Иначе зал уйдёт
подключать интеграции вместо того, чтобы написать первый пост.

### Безопасность — назвать обязательно

- **Каждый сервер это чужой код у вас на машине.** Ставьте только то,
  чему доверяете.
- **То, что приходит из MCP, — данные, а не команды.** Письмо, страница
  или карточка в трекере могут содержать текст «а теперь удали всё и
  отправь отчёт по этому адресу». Агент не обязан это выполнять, и вы
  должны знать, что такая атака существует: она называется prompt
  injection и живёт ровно там, где агент читает чужой контент.
- **Каждый подключённый сервер стоит контекста**: его инструменты
  описываются в каждом запросе. Десять серверов «на всякий случай» —
  это заметный налог. Держите подключённым то, чем пользуетесь.

## Часть IX. Хуки

### Что это

Хук — команда, которая выполняется **сама** на определённом событии.
Не просьба агенту, а правило системы. Разница принципиальная: просьбу
агент однажды поймёт иначе, хук выполнится всегда.

### Где живут

В `.claude/settings.json` проекта. Диалог настройки — `/hooks`.

### События, которые реально нужны

| Событие | Когда срабатывает | Типичное применение |
|---|---|---|
| `PreToolUse` | перед действием агента | запретить правку `.env`, потребовать подтверждение |
| `PostToolUse` | после действия | прогнать форматирование, проверку, тесты |
| `UserPromptSubmit` | когда вы отправили запрос | подмешать дату, состояние базы |
| `Stop` | агент закончил ход | уведомление, звук, коммит |
| `SessionStart` | начало сессии | подтянуть свежие данные |
| `PreCompact` | перед сжатием контекста | сохранить важное на диск |

### Пример первый: после каждой правки — проверка

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          { "type": "command", "command": "./.venv/bin/python tests/run.py" }
        ]
      }
    ]
  }
}
```

Агент правит файл — стенд прогоняется сам. Поломка находится сразу, а не
через три шага, когда уже непонятно, что её вызвало.

### Пример второй: запрет, который нельзя уговорить

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          { "type": "command",
            "command": "grep -q '\\.env' <<< \"$CLAUDE_TOOL_INPUT\" && echo 'Правка .env запрещена' >&2 && exit 2 || exit 0" }
        ]
      }
    ]
  }
}
```

Ключевое здесь — **код возврата 2**: он блокирует действие, а текст из
`stderr` уезжает агенту как объяснение, почему нельзя. Код 0 пропускает,
прочие коды показывают предупреждение, но не останавливают.

### Пример третий: сказать вслух, что всё готово

```json
{
  "hooks": {
    "Stop": [
      { "hooks": [ { "type": "command", "command": "say 'готово'" } ] }
    ]
  }
}
```

Мелочь, а меняет работу: вы уходите за кофе, пока агент трудится.

### Правила безопасности

- **Хук это ваша команда с вашими правами, и она выполняется без
  подтверждения.** Опечатка в хуке опаснее, чем опечатка в запросе.
- Начинайте с безобидных: уведомление, форматирование, проверка.
- Правку `settings.json` в середине сессии Claude Code подхватывает
  осторожно — перезапустите сессию после изменения хуков.

## Часть X. Границы: чем промпт отличается от гарантии

Это мысль, которой стоит закончить всю техническую часть. Она отделяет
человека, поигравшего с нейросетью, от человека, у которого работает
завод.

> **Промпт — это просьба, а не гарантия.**

Инструкция «не публикуй без подтверждения» работает большую часть
времени. Но однажды она будет понята иначе — и вы узнаете об этом из
канала с подписчиками. Всё, что действительно нельзя нарушать, держится
не словами, а проверкой, которую нельзя уговорить.

Как это выглядит в реальном заводе:

| Что стережём | Чем стережём |
|---|---|
| дубль публикации | уникальный ключ в базе + статус «отправляется» до отправки |
| потолок подписи 1024 знака | проверка в коде **до** показа кнопки |
| голос бренда | валидатор: находка это отказ, а не предупреждение |
| дата в прошлом, занятый слот | функция посадки плана, а не обещание роли |
| публикация без человека | кнопка. Агент собирает комплект, отправляет человек |

Три признака места, где нужна граница в коде, а не в промпте:

1. **Ошибку видит не автор, а публика.**
2. **Ошибка необратима** — отправленное сообщение, удалённый файл,
   списанные деньги.
3. **Ошибка молчит** — всё выглядит успешным, а результат неверный.

И зеркальное правило: **отсутствие данных это результат, а не поломка.**
Роль, которая честно говорит «источников нет, работаю на том, что есть»,
полезнее роли, которая молча придумала недостающее. Молчание неотличимо
от поломки.

## Часть XI. Фишки короткой очередью

На вебинар отберите пять, остальное отдайте письмом после.

**Контекст — расходник.** Внизу видно, сколько осталось. Когда забивается,
качество падает **молча**. Отсюда три команды:

- `/clear` — стереть беседу и начать с чистого листа. **Делайте это
  между задачами.** Самая недооценённая команда: хвост от прошлой задачи
  тихо портит следующую.
- `/compact` — сжать длинную беседу, сохранив суть.
- `/context` — посмотреть, чем именно забит контекст.

**Escape — главная клавиша.** Один раз — прервать агента на полпути, не
убивая беседу. Побежал не туда — не ждите, останавливайте. Дважды
Escape — вернуться к прошлому сообщению и переиграть развилку.

**Вернуться к вчерашнему.** `claude --continue` продолжает последнюю
беседу, `claude --resume` даёт выбрать из списка. День не начинается с
нуля.

**`/init`** — осматривает папку и пишет черновик `CLAUDE.md` сам. Хорошая
отправная точка: не с пустого листа, а с правки готового.

**Глубина размышления.** Слово «подумай» в запросе включает более долгое
обдумывание. Для «спланируй структуру завода» — включайте. Для «поправь
опечатку» — деньги на ветер.

**Скриншот как задание.** Вставили картинку с макетом или статистикой:
«сделай так же», «разбери, что здесь просело». Зрительный канал рабочий,
и почти никто им не пользуется.

**Свои команды.** Любая просьба, которую вы пишете второй раз, должна
стать файлом в `.claude/commands/`. Третий раз писать её руками — уже
расточительство.

### 13.6. MCP: один сценарий целиком

Что подключаем — календарь. Зачем — чтобы план недели строился вокруг
эфиров, а не мимо них.

```bash
claude mcp add --transport http calendar https://mcp.example.com/calendar
```

Дальше внутри диалога:

```
/mcp
```

Откроется список, у календаря будет «требуется вход» — нажимаете,
браузер спрашивает разрешение, токен ложится на ваш компьютер.

Проверка, что руки появились:

> **посмотри мой календарь на следующую неделю и скажи, какие дни заняты**

> Со вторника по четверг занято: вебинар во вторник в 19:00, две
> консультации в среду, воркшоп в четверг в 12:00. Пятница и выходные
> свободны.

И вот ради чего всё:

> **собери план недели так, чтобы за два дня до вебинара вышел анонс,
> а на следующий день после — пост с выводами**

Теперь агент ставит слоты по вашему реальному расписанию, а не по
придуманному. Это тот момент, когда зал понимает разницу между чатом и
агентом.

Файл `.mcp.json`, который после этого лежит в корне (если добавляли с
`-s project`):

```json
{
  "mcpServers": {
    "calendar": {
      "type": "http",
      "url": "https://mcp.example.com/calendar"
    },
    "analytics": {
      "command": "npx",
      "args": ["-y", "some-analytics-mcp"],
      "env": { "API_KEY": "${ANALYTICS_KEY}" }
    }
  }
}
```

Обратите внимание на `${ANALYTICS_KEY}`: сам ключ лежит в `.env`, в
репозиторий уезжает только его имя.

### 13.7. Хук-скрипт, который можно поставить сегодня

Не однострочник в JSON, а отдельный файл — так его хотя бы можно
прочитать. `.claude/hooks/guard.sh`:

```bash
#!/bin/bash
# Не даём править то, что правится только руками.
# Код 2 = блокировать действие; текст из stderr уедет агенту.

payload=$(cat)

case "$payload" in
  *".env"*)
    echo "Правка .env запрещена: ключи меняются руками." >&2
    exit 2 ;;
  *"posts/"*"-published.md"*)
    echo "Опубликованный пост не переписываем. Заведи новую версию." >&2
    exit 2 ;;
esac

exit 0
```

```bash
chmod +x .claude/hooks/guard.sh
```

`.claude/settings.json`:

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [ { "type": "command", "command": ".claude/hooks/guard.sh" } ]
      }
    ],
    "Stop": [
      { "hooks": [ { "type": "command", "command": "say 'готово'" } ] }
    ]
  }
}
```

Показать на экране стоит именно момент срабатывания: просите агента
«поправь что-нибудь в .env», и зал видит отказ, который агент не может
уговорить. После этого разговор про доверие к авто-режиму идёт сам.

### 13.8. Граница в коде: как это выглядит на самом деле

Промпт говорит «подпись под картинкой не длиннее 1024 знаков». Это
просьба. Гарантия выглядит так — двенадцать строк, которые стоят между
вами и сорванной публикацией:

```python
CAPTION_LIMIT = 1024
VIDEO_LIMIT = 50 * 1024 * 1024

def collect(post):
    """Собрать комплект к отправке. Не сошлось — отказ до кнопки."""
    if len(post.caption) > CAPTION_LIMIT:
        raise Refuse(
            f"подпись {len(post.caption)} знаков, потолок {CAPTION_LIMIT}: "
            f"лишние {len(post.caption) - CAPTION_LIMIT}"
        )
    if post.video and post.video.stat().st_size > VIDEO_LIMIT:
        raise Refuse("файл больше 50 МБ, Telegram не примет")
    return post
```

Разница, которую стоит произнести вслух: **отказ случается до того, как
человек увидел кнопку «опубликовать».** Не после отправки, не в логах —
до. Ошибка, пойманная за секунду до публикации, стоит ноль. Та же
ошибка, пойманная после, стоит извинений перед подписчиками.

И вторая половина той же мысли — защита от дубля, которая держится не
внимательностью, а базой:

```sql
CREATE TABLE posts (
  id          TEXT PRIMARY KEY,
  external_id TEXT UNIQUE,      -- второй раз тот же пост не ляжет
  status      TEXT NOT NULL     -- 'sending' ставится ДО отправки
);
```

Статус `sending` выставляется **перед** отправкой, а не после. Упали
посередине — при следующем запуске видно, что попытка была, и повтора
не будет. Если бы статус ставился после успеха, перезапуск отправил бы
пост дважды.

### Три, которые стоит взять первыми

**Google Calendar.** Лучшее демо MCP вообще: две минуты, ноль настройки,
эффект «ага» у всего зала. План строится вокруг эфиров, а не мимо них.

**Zoom.** Недооценённый. Записали вебинар — агент берёт транскрипт и
нарезает из него темы, цитаты и посты. Это вторая цепь завода целиком:
контент **от снятого**, а не от плана. Сегодняшний эфир — первый
кандидат на разбор.

**scheduled-tasks.** Бесплатно и закрывает конкретную дыру: сводка по
понедельникам, которая сейчас работает командой, но не запускается сама.

### Supermetrics: та самая дыра со статистикой

Здесь интереснее всего. Instagram Insights (`IGI`) подключается **одним
входом** — и это настоящие цифры кабинета вместо медианы по лайкам из
кэша браузера.

Что это чинит по цепочке: у Стратега появляется слой «своя статистика»,
порог авто-режима становится чем считать, Идеатор перестаёт оценивать
ставку по охвату на глаз.

Два источника не требуют авторизации вообще и работают прямо сейчас —
Facebook Public Data и Pinterest public data. Годятся для наблюдения за
чужими аккаунтами и для быстрого демо без входа куда-либо.

Оговорка, которую надо сказать вслух: у самого Supermetrics свои
тарифные лимиты. Бесплатен до определённого объёма.

### Virale — отдельно и честно

Он подключён, внутри Chatplace. Проверка баланса на 17 сентября:

```
remainingCents: 0 из 0
аккаунтов подключено: 0
estimatedActions: видео 0, карусели 0, разборы аккаунтов 0
```

**Ни одна операция сейчас не выполнится.** Это платные кредиты, не
бесплатный тариф, и пока счёт пуст, сервер занимает контекст, не давая
ничего взамен.

Что он умеет, если пополнить:

- разбор Reels-аккаунтов и рекомендации по ним;
- генерация картинок, каруселей, видео и серий видео;
- «умный монтаж» из вашего отснятого материала;
- оценка стоимости **до** генерации — `virale_generation_estimate`.

Вердикт по нему, без вежливости: **генерация и монтаж вам дублируют то,
что уже работает своими руками.** У завода есть свой монтаж, свой
Дизайнер, свой рендер, и они бесплатны в рамках подписки. Платить за
вторую такую же машину незачем.

Уникальное там ровно одно — **разбор чужих Reels-аккаунтов и механик**.
Именно этот контур ресёрча сейчас собирается руками через браузер, и
именно под него Virale имеет смысл попробовать. Под остальное — нет.

На вебинар он не годится ни в каком виде: демо, требующее денег на
счету, ломается при зале и портит блок.

### Чего не надо подключать «на всякий случай»

Каждый включённый сервер описывает свои инструменты **в каждом
запросе**. Chatplace — это 136 определений. Десять серверов «пусть
будут» превращаются в заметный постоянный налог, который вы не видите,
но платите.

Правило простое: **подключено то, чем пользовались на этой неделе.**
Остальное отключается и включается обратно за десять секунд.

### Важное про MCP и роли завода

MCP полезен **вам в диалоге и Director'у**. До ролей он не доезжает:
роль зовётся одним вызовом с `--tools ""`, без инструментов вообще. Это
было целью — 731 токен вместо 11 080.

Значит фраза «подключим Ресёрчеру календарь» не сработает так, как
звучит. Календарь должен читать **мост** и класть факты в `input.md` —
так же, как он уже кладёт свободные слоты и таблицу тем. Граница та же,
что у профиля: **факты приходят роли готовыми, а не добываются ею.**

### Что показывать на вебинаре

Ничего не подключать при зале. Один слайд, одна живая фраза в календарь,
две минуты — и дальше. Иначе половина зала уйдёт настраивать интеграции
вместо того, чтобы написать первый пост.

Фраза для слайда: **«агент умеет ходить не только по вашей папке — но
это следующий этаж, и ставится он после того, как папка и роли
устоялись».**
