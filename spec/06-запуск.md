# 06. Запуск локально и тестовый прогон

Цель: замкнуть цепь **онбординг → план → дашборд → тексты → публикация в
Telegram** на тестовом канале, локально, через polling.

---

## Что понадобится

| Что | Зачем |
|---|---|
| Python 3.11+ | `aiogram 3`, APScheduler |
| Ключ Anthropic API | роли |
| Telegram-аккаунт | BotFather, тестовая группа и канал |
| `cloudflared` или `ngrok` | туннель для Mini App |

---

## Шаг 1 · Создать семь ботов

В BotFather, `/newbot` семь раз. Имена продуктовые, не персональные: боты
общие на всех тенантов.

| Роль | Имя | Username (пример) |
|---|---|---|
| 🤝 | Ассистент \| Контент-завод | `cf_assistant_bot` |
| 🔍 | Ресёрчер \| Контент-завод | `cf_research_bot` |
| 🎯 | Стратег \| Контент-завод | `cf_strategy_bot` |
| ✍️ | Редактор \| Контент-завод | `cf_editor_bot` |
| 🎬 | Редактор Reels \| Контент-завод | `cf_reels_bot` |
| 🎨 | Дизайнер \| Контент-завод | `cf_design_bot` |
| 📤 | Публикатор \| Контент-завод | `cf_publisher_bot` |

**Обязательно для Ассистента:**

```
/setprivacy → @cf_assistant_bot → Disable
```

Без этого он не увидит обычные сообщения в группе и онбординг не заработает.

Аватарки: `/setuserpic`. Не косметика — по ним человек различает, кто говорит.

Токены сложить сразу, потом BotFather их не покажет повторно.

---

## Шаг 2 · Тестовая группа и канал

1. Создать группу → добавить любого второго человека или бота → **преобразовать
   в супергруппу** (Telegram делает это сам при включении топиков)
2. Настройки группы → **Темы (Topics) → включить**
3. Добавить все семь ботов
4. Ассистента сделать **админом** с правом **«Управление темами»**
5. Создать пустой канал `Контент-завод тест`, добавить Публикатора админом
   с правом публикации
6. Записать `chat_id` группы: `@userinfobot` или из логов первого апдейта

Канал держать **приватным** до конца теста.

### Direct Link Mini App

## Шаг 3 · Репозиторий

> ⚠️ **Репозиторий и `.env` не кладутся в синхронизируемую папку.** Семь
> токенов ботов и ключ Anthropic уехали бы в облако, а клиент синхронизации
> ломал бы файлы, которые бот пишет на ходу. Держать в `~/code/content-factory`
> или где угодно вне Nextcloud.
>
> Папка `Brands/` тоже рабочая и локальная. Выгрузка в Nextcloud — отдельный
> односторонний шаг, когда бот не пишет.

Раскладка репозитория — в `README.md`. Здесь она была копией и
разошлась: обещала `flow_onboarding.py`, `researcher.md` и три
валидатора, которых нет.

Промпты ролей — **отдельные markdown-файлы, не строки в коде.** Их правят чаще
всего, и правка не должна требовать деплоя.

## Шаг 4 · `.env`

```bash
ANTHROPIC_API_KEY=sk-ant-...

BOT_ASSISTANT=...
BOT_RESEARCH=...
BOT_STRATEGY=...
BOT_EDITOR=...
BOT_REELS=...
BOT_DESIGN=...
BOT_PUBLISHER=...

ALLOWED_CHATS=-1001234567890        # allowlist, обязательно
BRANDS_PATH=~/code/content-factory/Brands
MINIAPP_URL=https://<туннель>.trycloudflare.com
MINIAPP_SECRET=...                  # для подписи startapp-токенов
DB_PATH=./factory.db
DEFAULT_TZ=Europe/Moscow
LLM_BUDGET_PER_TENANT_DAY=200       # предохранитель от разгона
```

`ALLOWED_CHATS` не опционально: бота может добавить кто угодно, и без
allowlist он начнёт работать в чужой группе.

`LLM_BUDGET_PER_TENANT_DAY` — потолок вызовов модели на тенанта в сутки.
Круги переделки ограничены двумя, но цикл может закольцеваться иначе, и лучше
упереться в счётчик, чем в счёт.

## Шаг 5 · Первый запуск

```bash
./.venv/bin/pip install aiogram anthropic apscheduler python-dotenv pypdf python-docx
./run.sh
```

Запускать `main.py` напрямую нельзя, если стоит автозапуск через
`launchd`: агент тут же поднимет свой процесс, и два поллинга заглушат
друг друга. Подробности в `CLAUDE.md`.

Семь поллеров, но с разным набором обновлений:

```python
ASSISTANT_UPDATES = ["message", "edited_message", "my_chat_member", "callback_query"]
WORKER_UPDATES    = ["callback_query"]
```

Шесть рабочих ботов не читают сообщения, но обязаны получать нажатия своих
кнопок: `callback_query` приходит тому боту, который отправил сообщение.
Забыть про это — получить кнопки, которые не работают, и вечный часик на них.

**Что должно произойти:** Ассистент ловит `my_chat_member`, видит себя
админом с правом управления темами и создаёт десять топиков через
`createForumTopic`.

```
🤝 Собрал структуру: 10 топиков. Настраивать ничего не надо.
   Начнём с тебя. Кто будет говорить: ты или завод?
```

Если топики не создались — проверить: супергруппа, а не группа; Topics
включены; Ассистент админ; право «Управление темами» стоит.

## Шаг 6 · Mini App через туннель

```bash
cloudflared tunnel --url http://localhost:8080
```

Полученный `https://` вписать в `MINIAPP_URL` и **перезапустить бота**:
Telegram требует HTTPS для Mini App, `localhost` не примет.

⚠️ Бесплатный туннель меняет адрес при каждом запуске. Для теста нормально,
для постоянной работы нужен домен.

## Шаг 7 · Приёмка

Всё, что проверяется без человека, проверяет стенд:
`./.venv/bin/python tests/run.py`. Дублировать его списком галочек здесь
незачем — список устаревает молча, а стенд падает громко.

Руками проходится то, чего стенд не достаёт:

1. **Онбординг целиком.** Маска, ссылки на публичный канал, распаковка,
   три спорных места, запись `core.md`. Приёмка: в папке бренда появился
   `core.md`, пометки `[уточнить факт]` стоят там, где данных не было,
   и ничего не выдумано.
2. **Дашборд на телефоне.** Фильтр по площадке, одна тема на переделку
   с комментарием, отправка. Приёмка: «переделать» не уходит без
   комментария, ссылка, пересланная постороннему, чужой план не открыла.
3. **Живая публикация.** Утвердить пост, нажать «опубликовать» дважды.
   Приёмка: пост вышел один раз, превью совпало с тем, что вышло,
   в базе `pub`, `link` и `external_id`.
4. **Правка тона.** Приёмка: правка легла в `voice-corrections.md`, а
   следующий текст её учёл.

> ⚠️ **На ноутбуке расписание не работает.** Машина уснула — публикация
> в 10:00 не случилась. Пропущенный слот **не публикуется задним
> числом**, он уходит в `skip` с причиной: пост, вышедший через сутки
> после слота, хуже невышедшего.

## Как вносить правки потом

Три контура, путать нельзя.

| Что меняется | Как | Кто |
|---|---|---|
| **Профиль бренда** — голос, палитра, стоп-слова, площадки | диалогом в чате, `core.md` версионируется | пользователь |
| **Промпты ролей** — общая механика продукта | файлы `roles/*.md`, git, версия в шапке | ты |
| **Код** — боты, дашборд, валидаторы | обычный git | разработчик |

**Пользователь никогда не правит промпты, ты никогда не правишь чужой
`core.md`.**

### Правка от пользователя, которая должна стать продуктовой

Ассистент помечает такую правку как `candidate_for_core` в отдельном файле.
Раз в месяц ты смотришь список и решаешь, что уходит в общий промпт.

Пример: три разных клиента попросили убрать восклицательные знаки — значит это
не свойство бренда, а общий признак машинного текста, и правило уезжает в
`roles/frame-text.md` — каркас пишущей роли.

### Версионирование промптов

Шапка каждого файла роли:

```markdown
<!-- role: strategist · version: 1.2 · updated: 2026-08-20 -->
```

Рядом `roles/CHANGELOG.md`:

```markdown
## 1.2 — 2026-08-20
Добавлено правило узкого места: план собирается под bottleneck,
фиксированная пропорция стала запасной.
Причина: на тесте план размазывался ровным слоем при явной дырке в конверсии.
```

Без этого через два месяца будет непонятно, почему Редактор вдруг стал писать
иначе.

### Порядок внесения правки в промпт

1. Правка в `roles/*.md`, поднять версию, строка в `CHANGELOG.md`
2. Прогнать тот же тестовый сценарий на тестовом канале
3. Сравнить выход с прошлым: стало лучше именно в том, ради чего правил
4. Влить

**Правки промптов не накатываются пачкой.** Одна правка — один прогон:
иначе непонятно, какая из трёх сработала, а какая сломала.
