# 05. Дашборд согласования

Рабочий прототип:
https://claude.ai/code/artifact/6fbb1c63-c02f-49e2-9b8b-ba8eb39b527d

Показывает весь путь: сообщение Стратега в чате → тап → Mini App выезжает
поверх → решения → ответ бота. Открывать на телефоне.

---

## Почему Mini App

| Вариант | Плюс | Минус |
|---|---|---|
| Инлайн-карточки по одной | ничего не разрабатывать | 7 тем = 7 сообщений, фильтров нет |
| **Mini App** | таблица, фильтры, массовые действия, один пакет назад | нужно написать страницу |
| Внешняя ссылка | быстро | выход из Telegram, на телефоне неудобно |

Для семи тем с фильтрами инлайн-карточки не годятся физически.

## ⚠️ Как открывать: только Direct Link Mini App

Инлайн-кнопка с `web_app` **работает лишь в личке с ботом**. Наша карточка
приходит в топик супергруппы, там она не запустится. Это блокер, и его надо
знать до написания кода.

Рабочий способ в группе — **Direct Link Mini App**: приложение регистрируется
в BotFather через `/newapp`, а кнопка становится обычной `url`-кнопкой:

```
t.me/cf_strategy_bot/plan?startapp=<token>
```

Такая ссылка открывается откуда угодно, включая групповые топики.

### Как приложение узнаёт, чей это план

В `initData` для Direct Link **нет `chat_id` группы** — только `user`,
`chat_type` и непрозрачный `chat_instance`. Значит тенант передаётся через
`startapp`.

**`startapp` не должен содержать сырой `chat_id`**: параметр видно в ссылке,
и перебор дал бы доступ к чужим планам. Передаётся короткоживущий подписанный
токен:

```
token = HMAC(secret, chat_id + batch_id + exp)   →  живёт 24 часа
```

Сервер разворачивает токен в пару (тенант, батч), затем **обязательно**
проверяет `initData` по хешу от токена бота и сверяет, что `user.id` состоит
в этой группе. Без второй проверки ссылку можно переслать постороннему.

### Возврат решений

`sendData()` здесь недоступен: он работает только для Mini App, запущенных
кнопкой обычной клавиатуры. Решения уходят обычным POST на свой эндпоинт с
`initData` в теле, ответ бот шлёт в чат уже сам.

## Что даёт Telegram бесплатно

| API | Что даёт |
|---|---|
| `themeParams` | цвета из темы пользователя, светлая и тёмная |
| `MainButton` | нативная кнопка внизу, рисовать не нужно |
| `HapticFeedback` | отклик на нажатие |
| `BackButton` | системная кнопка назад |
| `expand()` | на весь экран при открытии |

## Правила мобильной вёрстки

1. **Никаких таблиц.** Карточка на всю ширину, вертикальный список.
   Горизонтальный скролл внутри контента запрещён.
2. **Тач-цель 44pt минимум.**
3. **Хук виден всегда.** Оценить тему по одному заголовку нельзя. Обрезается
   по двум строкам.
4. **Решённое схлопывается** в строку с датой. Список укорачивается на глазах.
5. **Одна рука, большой палец.** Действия внизу карточки, фильтры вверху —
   их трогают редко.
6. **«Взять» главная кнопка.** Залита акцентом, шире остальных: в 80% случаев
   жмут её.

## Три действия

| Кнопка | Что происходит |
|---|---|
| **Взять** | тема в план, статус `idea` |
| **Переделать** | открывается поле «что не так», тема возвращается Стратегу |
| **Убрать** | тема удаляется из батча |

**Переделать без комментария не отправляется.** Кнопка неактивна, пока не
написано. Иначе Стратег переписывает вслепую и приносит то же самое другими
словами.

## Живой баланс

Счётчик внизу пересчитывается на каждом действии и предупреждает **до**
отправки:

```
прогрев 6 · продукт 0 · личное 1
Убраны оба продуктовых. Неделя без единого касания продажи.
```

Ловит самую частую ошибку согласования: человек убирает продуктовые темы,
потому что «неловко продавать», и через месяц удивляется отсутствию заявок.

Предупреждение не блокирует, решение за человеком.

## Счётчик и фильтр

Счётчик вверху считает **видимое в текущем фильтре**: включила Instagram —
стало «0 из 2». Кнопка отправки остаётся общей, она отправляет все решения
недели.


## Тема оформления

**Дашборд оформляется палитрой и шрифтами клиента, а не продукта.** Всё нужное
уже собирается на онбординге в `design/`: палитра, шрифты, радиусы. Тема
генерируется на тенанта автоматически.

Это аргумент в продаже: человек открывает рабочий инструмент и видит свой
бренд, а не чужой интерфейс.

Прототип собран на дизайн-системе lily.space: молоко `#F8F5F1`, песок
`#F1ECE5`, карточка `#FCFBF8`, графит `#1F1F1F`, камень `#6B6762`, терракота
`#C97C5D`, сажа `#A8B4A5`. Manrope для заголовков и чисел, Inter для тела.
Радиусы 20 / 14 / 8, пилюли на 100. Пропорция 80 неутралей / 15 графита /
5 акцента соблюдена: терракота стоит только на кнопке отправки, счётчике и
взятых темах.

⚠️ **Шрифты вшиваются в страницу**, не подключаются по ссылке. Внутри Mini App
внешние загрузки могут не пройти, и подгрузка молча упадёт на системный шрифт.
Manrope и Inter засабсечены под кириллицу и латиницу и весят 56 КБ на три
начертания.

**Тёмная тема выводится из токенов системы, не придумывается.** У lily.space
уже есть словарь для тёмных блоков: `--surface-inverse`, `--text-on-dark`,
`--accent-on-dark: #E9A886`. На графитовом фоне работает мягкая терракота,
обычная слишком глухая.

## Две палитры в одном экране

Шапка, бабблы и поле ввода принадлежат Telegram и остаются нейтральными.
Внутри Mini App работает бренд. Контраст на переходе читается сразу: вышел из
мессенджера, попал в свой продукт.

## Что режем в v1

| Оставляем | На потом |
|---|---|
| фильтр по площадке | фильтры по цели, формату, дню |
| три действия | свайпы, перетаскивание, изменение дат |
| «Взять все» | «Взять всё в Telegram» |
| строка баланса | предупреждения с объяснением |
| отправка пакетом | сохранение черновика решений |

Урезанная версия — один HTML-файл примерно на 400 строк без фреймворков.

## Запасной путь

`[📋 Списком в чат]` — те же темы карточками по одной с теми же тремя
кнопками. Медленнее, но работает везде, где Mini App недоступен.

## Три режима одного кода

| Режим | v1 | Почему |
|---|---|---|
| **План** | ✅ дашборд | сравнение тем и фильтры дают выигрыш |
| **Тексты** | карточки в чат | пост надо прочитать целиком, дашборд не выигрывает |
| **Очередь** | список в чат | мало элементов, решений почти нет |
