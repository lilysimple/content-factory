# 00. Архитектура

## Главное ограничение платформы

**Бот Telegram никогда не получает сообщения от другого бота.** Это жёсткое
ограничение Bot API, обойти его можно только юзерботами на MTProto с реальными
номерами — серая зона ToS и лишняя сложность.

Отсюда следует всё остальное: **Telegram это интерфейс, а не шина обмена.**
Агенты общаются между собой внутри оркестратора структурированными данными,
а в чат выходит только то, что человеку надо увидеть или утвердить.

Плюс лимиты: ~20 сообщений в минуту в один чат, 30 в секунду суммарно.
Агентская «переписка» в чате сожгла бы их за секунды.

## Семь ботов, общих на всех тенантов

Не по семь ботов каждому клиенту: BotFather даёт около двадцати ботов на
аккаунт, и создавать их вручную каждому невозможно.

```
🤝 Ассистент      ──┬── группа клиента A   (tenant = chat_id_A)
🔍 Ресёрчер       ──┼── группа клиента B   (tenant = chat_id_B)
🎯 Стратег        ──┼── группа клиента C
✍️ Редактор       ──┤
🎬 Редактор Reels ──┤
🎨 Дизайнер       ──┤
📤 Публикатор     ──┘
```

Бот может состоять в неограниченном числе групп. Отсюда: семь вебхуков всего,
одна кодовая база, `tenant = chat_id` супергруппы.

**Сообщения людей слушает только Ассистент.** Остальные шесть не читают чат.

> ⚠️ **Но нажатия кнопок читает каждый.** `callback_query` доставляется тому
> боту, который **отправил** сообщение с кнопкой. Карточку плана шлёт Стратег
> своим токеном — значит нажатие придёт в поток обновлений Стратега, а не
> Ассистента. Схема «слушает один» в чистом виде не работает.

### Правильная схема обновлений

Все семь ботов держат соединение, но с разным `allowed_updates`:

| Бот | `allowed_updates` |
|---|---|
| **Ассистент** | `message`, `edited_message`, `my_chat_member`, `callback_query` |
| **Остальные шесть** | `callback_query` — и больше ничего |

Все шесть потоков `callback_query` сходятся в один оркестратор. Разделение по
токенам остаётся только на отправке: каждая роль говорит своим лицом.

Так же ловятся ошибки: `callback_query` обязан получить `answerCallbackQuery`
в течение нескольких секунд, иначе у человека вечно крутится часик на кнопке.

### Настройки ботов

| Бот | Privacy mode | Права |
|---|---|---|
| Ассистент | **выключен** (`/setprivacy` → Disable) | админ группы, `can_manage_topics` |
| Остальные шесть | не важно, сообщения не читают | обычный участник группы |
| Публикатор | — | плюс админ канала с правом публикации |

### Очередь отправки

Лимит ~20 сообщений в минуту в один чат. Батч из семи карточек плюс пинги
подходит к нему вплотную. Отправка идёт **через одну очередь с троттлингом на
`chat_id`**, а не напрямую из ролей. Ошибку `429 Too Many Requests` с
`retry_after` обрабатывать обязательно, иначе Telegram начнёт молча резать.

### Безопасность мультитенантности

Бота может добавить кто угодно. Строгий allowlist обязателен:

- апдейт из неизвестного `chat_id` → предложение онбординга либо отбой,
  но никакой работы;
- `my_chat_member` при добавлении → проверка, кто добавил;
- один `chat_id` — одна папка бренда, связь один к одному.

### Белый лейбл

Свои боты клиента — платный тариф v2. Токены принимаются **только через
веб-дашборд**, никогда в чат: сообщения хранятся и видны всем админам группы.

## Подключение нового тенанта

Что делает **пользователь** руками, и что делает система за него.

| Шаг | Кто | Сколько |
|---|---|---|
| 1. Создать группу и включить темы | человек | ~40 сек |
| 2. Добавить Ассистента админом | человек, одна ссылка | ~10 сек |
| 3. Добавить шесть остальных ботов | человек, шесть ссылок | ~90 сек |
| 4. Создать структуру топиков | **система** | мгновенно |
| 5. Распаковать бренд, собрать ЯДРО | **система** + 12 ответов | 10–15 мин |
| 6. Подключить канал публикации | человек, одна ссылка | ~20 сек |

Итого около **трёх минут возни** плюс разговор. Всё остальное система делает
сама.

### Шаг 2: одна ссылка вместо инструкции

```
t.me/cf_assistant_bot?startgroup=true&admin=manage_topics+delete_messages
```

Deep-link `startgroup` открывает диалог выбора группы **и сразу проставляет
галочки нужных прав**. Человеку не надо искать пункт «Управление темами» в
настройках — самое частое место, где люди застревают.

### Шаг 3: главная слабость схемы

> ⚠️ **Бот не может добавить другого бота в группу.** В Bot API нет метода
> `addChatMember` вообще. Значит шесть оставшихся «лиц» пользователь добавляет
> руками, по одному.

Смягчаем проводкой со шкалой готовности. Ассистент подписан на `chat_member`
и **видит вживую**, кто уже зашёл:

```
🤝 Ассистент
Осталось позвать команду. Шесть ссылок, каждая в один тап.
Группу выбирать не надо, я подставил.

🎯 Стратег      → добавить
✍️ Редактор     → добавить
🔍 Ресёрчер     → добавить
🎨 Дизайнер     → добавить
🎬 Reels        → добавить
📤 Публикатор   → добавить

Пришли 0 из 6. Жду, отмечаю по мере появления.
```

Сообщение редактируется на каждом входе: `Пришли 3 из 6`. Когда все на месте —
переход к онбордингу автоматом, без команды.

### Цена решения «семь лиц»

Семь ботов вместо одного стоят пользователю **полторы минуты и шесть тапов**
на входе. Это реальная точка отвала для коробки.

Развилка на будущее, решать по данным первых пользователей:

| | Настройка | Ощущение |
|---|---|---|
| **Семь ботов** | 6 добавлений | команда людей в чате |
| **Один бот с префиксами ролей** | 1 добавление | «бот с режимами» |

Код отличается словарём `роль → токен`, так что переключение дешёвое.
Разумный план: коробка на одном боте, семь лиц — как опция для тех, кому
зашло. Но проверять это на живых людях, а не гадать.

## Топики: десять

Супергруппа с включёнными Topics. Структуру создаёт Ассистент сам через
`createForumTopic` при добавлении в группу — человек не настраивает ничего.

| | Топик | Что там | v1 |
|---|---|---|---|
| 📌 | **General** | пульт: запросы человека, карточки на решение, пинги | ✅ |
| 🔍 | Ресёрч | дайджесты, источники, конкуренты | 🟡 |
| 🎯 | Стратегия | планы, рубрики, темы | ✅ |
| ✍️ | На ревью | тексты на утверждение | ✅ |
| 🎬 | Reels | сценарии, раскадровки | ⬜ |
| 🎨 | Дизайн | визуалы, итерации | ⬜ |
| 📸 | Фотобанк | фото от человека, индексируются автоматически | ⬜ |
| 📤 | Очередь | что и когда выходит | ✅ |
| 📊 | Метрики | дайджесты по факту | 🟡 |
| 🧾 | Логи | трейс агентов, замьючен | ✅ |

### Правило связи

Сообщение живёт **только в одном топике**, дублирования в Telegram не бывает.
Поэтому:

- **General читается всегда.** Туда идут запросы человека и всё, что требует
  его решения.
- **Топики читаются по ссылке.** Когда в ветке появился результат, в General
  падает однострочник с диплинком:

```
🎨 Дизайнер · карусель для понедельника готова → [открыть]
```

Ссылка вида `t.me/c/<chat_id>/<topic_id>/<message_id>` открывает ровно то
сообщение. `<chat_id>` здесь без префикса `-100`. Один тап туда, один назад.

### Две ловушки топиков

**У General нет `message_thread_id`.** Чтобы написать в General, поле просто не
передаётся. Передать `message_thread_id=1` — получить ошибку либо промах.
Хранить его в таблице `topics` как `NULL`, а не как единицу.

**Топик можно удалить руками.** Тогда сохранённый `topic_id` протухает, и
отправка падает с `TOPIC_DELETED`. На эту ошибку — пересоздать топик,
обновить запись и отправить повторно, а не падать.

**В чат выходят только артефакты и передачи.** Рассуждения, черновики и
промежуточные итерации уходят в `🧾 Логи`.

## Маршрутизация

Ассистент определяет, какой роли уходит запрос. Три сигнала по приоритету:

1. **Явное упоминание** — `@lily_strategist_bot дай ещё три темы`. Уходит
   адресату, классификатор не работает.
2. **Топик** — всё написанное в `🎨 Дизайн` по умолчанию идёт дизайнеру.
3. **Смысл** — классификация по словарю триггеров.

### Словарь триггеров

| Роль | Триггеры |
|---|---|
| 🤝 Ассистент | что в очереди · статус · что вышло · найди пост про · покажи ядро · добавь стоп-слово · поменяй правило · настрой |
| 🔍 Ресёрчер | сводка · дайджест · что нового · тренды · новости ниши · разбери конкурентов · разбери рилсы · статистика · метрики · что зашло |
| 🎯 Стратег | план · контент-план · темы · что постить · спланируй · идеи постов · пересобери рубрики · стратегия |
| ✍️ Редактор | напиши пост · текст · перепиши · поправь · сделай короче · адаптируй под · анонс · описание для YouTube |
| 🎬 Редактор Reels | сценарий · рилс · reels · shorts · суфлёр · сними ролик · хук |
| 🎨 Дизайнер | обложка · карусель · превью · оформи · карточки · визуал · сверстай |
| 📤 Публикатор | опубликуй · в очередь · перенеси на · когда выходит · отмени публикацию · расписание |

### Коллизии, разведённые явно

| Фраза | Куда | Почему |
|---|---|---|
| «когда выходит X» | 📤 Публикатор | расписание его |
| «что там с X» | 🤝 Ассистент | состояние его |
| «сделай рилс» | 🎬 Редактор Reels | сценарий первый, обложка приходит по цепочке |
| «оформи пост» | 🎨 Дизайнер | нет текста → сам позовёт Редактора |

**При неоднозначности не угадывать.** Ассистент спрашивает одной кнопкой:

```
«Сделай что-нибудь про новый Claude» — это пост или сценарий?
[✍️ Пост]  [🎬 Рилс]  [🎯 Сначала тему]
```

## Площадки

| Площадка | Публикация | Статистика | v1 |
|---|---|---|---|
| **Telegram** | Bot API, полный автомат | ⚠️ Bot API просмотры не отдаёт: MTProto, встроенная статистика от 50 подписчиков, TGStat или скриншоты ленты | ✅ |
| **Instagram** | Graph API: Business-аккаунт + FB Page + ревью приложения | Graph API insights | v2 |
| **YouTube** | Data API, OAuth владельца | Analytics API, окно +30 дней | v2 |

VK и LinkedIn исключены из проекта.

**Скриншоты работают всегда** и для всех площадок: человек кидает выгрузку в
`📊 Метрики`, Ресёрчер разбирает построчно. Это единственный способ, доступный
с первого дня.

**Авторизация площадок только через OAuth на веб-странице.** Токены в чат не
принимаются ни в каком виде.
