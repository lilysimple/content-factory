# Контент-завод

Семь агентов-ботов в супергруппе Telegram, которые производят и публикуют
контент по профилю бренда клиента. Коробочный мультитенантный продукт:
изоляция по `chat_id`, профиль клиента в отдельном репозитории.

Цепь замкнута: онбординг → план недели → текст или сценарий → макет →
публикация в Telegram.

| Где что | |
|---|---|
| `CLAUDE.md` | состояние проекта, запуск, правила, которые легко нарушить |
| `NOTES.md` | устройство подсистем и уроки, оплаченные поломками |
| `ARCHITECTURE.md` | как устроено целиком: два пути, мост, Director |
| `spec/` | восемь документов, `spec/README.md` — журнал решений |
| `tests/README.md` | стенд |

## Запуск

```bash
python3 -m venv .venv
./.venv/bin/pip install aiogram anthropic apscheduler python-dotenv pypdf python-docx
cp .env.example .env      # заполнить токены
./run.sh
```

Завод стоит на автозапуске через `launchd`, и `run.sh` перезапускает
именно агента. Поднимать `main.py` руками нельзя: Telegram разрешает
**один опрос на бота**, второй инстанс глушит первый.

Перед первым запуском — `spec/06-запуск.md`: семь ботов в BotFather,
`/setprivacy` → Disable у Ассистента, группа с включёнными темами и он же
администратором.

## Структура

```
bots/          registry (семь лиц, очередь отправки), topics, router, handlers
orchestrator/  роли: onboarding, strategy, editor, reels, design, publisher
               desk.py — общий каркас роли: выбор темы, память, кнопки
storage/       db (горячее состояние), brand (профиль на диске)
roles/         промпты, frame.md общий для всех
validators/    детерминированные проверки текста и сценария
design-pack/   эталонные макеты, общие для всех тенантов
tests/         стенд: семь офлайн-циклов, шесть живых
```

## Два репозитория

| Репозиторий | Что | Remote |
|---|---|---|
| `content-factory` | код, промпты, спека | GitHub, приватный |
| `content-factory-brands` | профили клиентов | локально, **наружу не пушится** |

В `Brands` коммерческие данные клиентов: позиционирование, цены, воронки,
цели по выручке. Поэтому `BRANDS_PATH` указывает на соседний репозиторий,
а не на папку внутри этого. Спека лежит в `spec/` рядом с кодом: правки
спеки и кода тогда ходят одним коммитом и не разъезжаются.
