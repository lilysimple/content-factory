# Контент-завод

Семь агентов-ботов в супергруппе Telegram, которые производят и публикуют
контент по профилю бренда клиента.

Спека: `Nextcloud/AI content/Content factory/Спека Telegram-завода/`

## Что уже работает

- Семь ботов поднимаются, каждый говорит своим лицом
- Два диспетчера с разными `allowed_updates` — нажатия слушают все семеро
- Автопровижининг десяти топиков при добавлении в группу
- Проверка прав до попытки создавать топики
- Пересоздание топика, удалённого руками
- Троттлинг отправки на `chat_id` и обработка `429`
- Маршрутизация: упоминание → топик → смысл, с явными коллизиями
- Онбординг до записи ЯДРА: маска, ссылки, файлы, распаковка, три спорных места
- Чтение источников: `t.me/s/` без токенов, сайты, pdf/docx/txt/md, экспорт Telegram
- Правка профиля из чата: файлом, ссылкой и словами, через подтверждение
- Ассистент отвечает моделью: профиль в контексте, состояние из БД
- Кеширование промптов: ~92% системного промпта в общем префиксе
- Исходники переезжают в `sources/uploads` и `voice-samples` бренда
- Валидатор `check_voice`
- SQLite со всей схемой

## Чего ещё нет

Шаги онбординга O4–O15 (референсы, фото, цифры, площадки, оформление),
дашборд согласования, публикация, метрики.

Стратег, Редактор, Reels, Дизайнер, Публикатор модель не зовут — отдают
честную заглушку. Вызывают только `unpack.py` и `reply.py`.

## Запуск

```bash
python3 -m venv .venv
./.venv/bin/pip install aiogram anthropic apscheduler python-dotenv pypdf python-docx
cp .env.example .env      # заполнить токены
./run.sh
```

`run.sh` сначала гасит старый экземпляр: Telegram разрешает **один опрос
на бота**, два инстанса глушат друг друга.

### Перед первым запуском

1. Семь ботов в BotFather. Ассистенту обязательно `/setprivacy` → **Disable**,
   иначе он не увидит сообщения в группе и онбординг не начнётся.
2. Группа → включить **Темы** → добавить Ассистента **администратором** с
   правом **«Управление темами»**.
3. `ALLOWED_CHATS` — id тестовой группы. Пустое значение принимает любой чат,
   так можно только локально.

Ссылка для шага 2, сразу с нужными правами:

```
t.me/<assistant_bot>?startgroup=true&admin=manage_topics+delete_messages
```

## Структура

```
bots/        registry (семь лиц, очередь отправки), topics, router, handlers
orchestrator/ onboarding, personas
storage/     db — горячее состояние
roles/       промпты, frame.md общий для всех
validators/  детерминированные проверки
Brands/      профили брендов, по одной папке на тенант
```

## Два правила, которые легко нарушить

**`callback_query` приходит боту, который отправил сообщение.** Поэтому
рабочие боты тоже поллятся, пусть и только на нажатия. Забыть — получить
кнопки, которые не работают.

**У General нет `message_thread_id`.** В базе он хранится как `NULL`, и при
отправке параметр не передаётся вовсе. Передать `1` — промахнуться.

## Два репозитория

| Репозиторий | Что | Remote |
|---|---|---|
| `content-factory` | код, промпты, спека | GitHub, приватный |
| `content-factory-brands` | профили клиентов | локально, наружу не пушится |

В `Brands` лежат коммерческие данные клиентов: позиционирование, цены,
воронки, цели по выручке. Поэтому `BRANDS_PATH` указывает на соседний
репозиторий, а не на папку внутри этого.

Спека живёт в `spec/` рядом с кодом: правки спеки и кода тогда ходят одним
коммитом и не разъезжаются.
