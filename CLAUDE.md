# Контент-завод — состояние проекта

Читается автоматически в начале каждой сессии. Держать актуальным **и
коротким**: всё, что здесь лежит, оплачивается контекстом на каждой
сессии, даже когда не нужно.

Коробочный мультитенантный продукт: семь агентов-ботов в супергруппе
Telegram производят и публикуют контент по профилю бренда клиента.
Изоляция по `chat_id`, профиль клиента в отдельном репозитории.

| Вопрос | Файл |
|---|---|
| Как устроено целиком: два пути, мост, Director, субагенты | `ARCHITECTURE.md` |
| Почему подсистема сделана так, чем оплачено | `NOTES.md`, по разделам |
| Что решено и не переоткрывается | `spec/README.md` |
| Требования по ролям | `spec/`, восемь документов |
| Маршрут миграции и замеры | `MIGRATION_TO_CLAUDE_CODE.md` |

Спека не дублирует код: промпты в `roles/*.md`, схема базы в
`storage/db.py`, приёмка в `tests/`. **`NOTES.md` не читается
автоматически** — берёшься за подсистему, открываешь её раздел.

## Где мы сейчас

Работают все семь ролей, цепь замкнута: сводка → план недели → текст или
сценарий → выбор фона → макет → публикация. Блокировок нет.

Фон Дизайнер показывает тремя вариантами и ждёт кнопку — дизайн ложится
на утверждённый кадр (`design.offer`, устройство в `NOTES.md`). Фотобанк
пополняется из альбома «Фото» (`tools/photos_pull.py`), сток добирает
нехватку по ключевым словам темы (`orchestrator/stock.py`,
`PEXELS_API_KEY`).

Вторая цепь идёт от снятого, а не от плана: файл или ссылка на эфир →
Монтажёр ставит границы (`roles/cut.md`) → код режет и рендерит →
подпись Редактора по просьбе → Публикатор. Стратега и Редактора Reels в
ней нет, тема заводится по факту съёмки. **Публикацию видео она пока не
достаёт:** `publisher.collect` собирает только PNG и требует текст поста,
так что «В очередь» на рилсе упрётся в «текста нет». Это следующая
работа.

**Первый пост опубликован 03.09** — `2026-09-03-telegram-01`, сообщение
245 в канале. Цепь плана замкнута не только на стенде: от сводки до
живой публикации она прошла целиком.

Канал — `PUBLISH_CHANNEL=@lilyspace1`, id `-1003821039599`, «Lily Space:
про жизнь в эпоху AI🌿»; `@lily_cf_publisher_bot` там администратор с
правом постить. Второй канал бренда `@lilyspace` заводом не ведётся.

**Публикация идёт в живой канал с подписчиками.** Показать превью и
дождаться явного согласия человека. Сам не отправлять.

Состояние базы **не переписывай сюда числами** — вшитая фраза переживает
то состояние, которое описывала, и это самый повторяющийся баг проекта.
Спрашивай базу:

```bash
./.venv/bin/python -c "
import sqlite3; c = sqlite3.connect('factory.db')
print(c.execute('select status, count(*) from themes group by status').fetchall())
print('posts:', c.execute('select count(*) from posts').fetchone()[0])"
```

## Как запустить

Завод на автозапуске через `launchd`, агент `space.lily.content-factory`:
поднимается при входе в систему и сам перезапускает упавший процесс.

```bash
cd ~/code/content-factory && ./run.sh
```

`run.sh` видит загруженный агент и перезапускает **через него**. Запускать
`main.py` напрямую нельзя: launchd тут же поднимет свой, получится два
поллинга и взаимный `Conflict`. На этом уже спотыкались дважды.

```bash
launchctl print gui/$(id -u)/space.lily.content-factory | grep -E "state|pid"
launchctl kickstart -k gui/$(id -u)/space.lily.content-factory
launchctl bootout gui/$(id -u)/space.lily.content-factory   # снять автозапуск
```

Поставить заново или на другой машине — `./deploy/install-agent.sh`.

- **Это агент, а не демон.** Стартует при входе в систему, не при загрузке
  Мака: демон работал бы от root без пользовательского окружения, и Chrome
  для рендера макетов там не поднимется.
- **Сон Мака останавливает завод.** Закрытая крышка это пауза.
- Только **один** экземпляр: Telegram разрешает один опрос на бота.
- **`SIGTERM` инстанс не берёт**, застряв в переподключении aiogram —
  нужен `kill -9`.
- Лог — `bot.log`.

## Чего нет

Шаги онбординга O4–O15 (референсы, фото, цифры, оформление), поэтому нет
`goals.md`, `sources.md`, дизайн-токенов. Стратег из-за этого работает на
запасной пропорции 60/20/20 и говорит об этом в «Контексте недели».
`platforms.md` заведён 31.08 руками, минуя онбординг.

Метрик по факту публикации нет: снимки через 24 часа, 72 часа и 7 дней не
снимаются. Своя статистика считается по публичной ленте канала целиком,
без привязки к слоту плана.

Модель зовут из восьми мест: `unpack.py`, `refresh.py`, `research.py`,
`reply.py`, `strategy.py`, `editor.py`, `reels.py`, `design.py` — все
через `agent.ask`. Мост зовёт её иначе, через Director, но **выходят они
в одно место**: `orchestrator/cli.py`, то есть в Claude Code по подписке.
Ключа Anthropic API у завода нет с 01.09 — ни в `.env`, ни в `config.py`,
и `cli.clean_env` не пускает его в подпроцесс, даже если он лежит в
окружении. Ключ увёл бы вызовы на API-тариф молча.

**Роль запускается вне репозитория.** Это выглядит странно и держится на
замере: `CLAUDE.md` ищется вверх по дереву, и в папке завода каждый вызов
роли тащит контекст Director — 10 660 токенов против 729. Мост наоборот
запускается в корне: ему `CLAUDE.md` и субагенты нужны. Границу держит
цикл 21.

**`--tools ""`, а не `--allowedTools ""`.** Первый снимает набор
инструментов, второй только права — определения всё равно едут в
контекст. Разница 11 080 токенов против 731 на каждом вызове, и на глаз
она невидима: ответ приходит одинаковый.

## Стенд

```bash
./.venv/bin/python tests/run.py           # офлайн, ~2 минуты
./.venv/bin/python tests/run.py --live    # плюс живые вызовы модели
```

Двенадцать офлайн-циклов, семь живых отдельно. Гонять перед каждым
коммитом: почти все поломки этого проекта нашлись именно так, а не в
работе. Стенд копирует базу и бренд в `tests/.sandbox` и чистит там
производные данные — без чистки тесты падают от того, что бот наработал за
день. Подробности — `tests/README.md`.

## Правила, которые легко нарушить

- **`callback_query` приходит боту, который отправил сообщение** — поэтому
  рабочие боты тоже поллятся, но только на нажатия.
- **У General нет `message_thread_id`**: в базе `NULL`, при отправке
  параметр не передаётся вовсе.
- **Инлайн-кнопка `web_app` работает только в личке.** Дашборд в группе —
  только Direct Link Mini App через `/newapp`.
- **Потолок сообщения 4096 знаков, подписи под картинкой — 1024.**
- **На Opus 5 нет `temperature`** (400) и **мышление включено по
  умолчанию**: `max_tokens` считает мышление вместе с ответом.
- **Slug бренда не меняется никогда** — на нём завязаны пути к артефактам.
- **`git` ищет репозиторий вверх по дереву.** Папка бренда без своего
  `.git` находит первый попавшийся выше, и `add -A` уносит туда всё
  подряд. Стережёт `brand._own_repo`.
- **Порядок блоков в системном промпте ломать нельзя** — кеш это
  совпадение префикса. Устройство — `NOTES.md`.

## Где границу держит код

Промпт это просьба, а не гарантия. Восемь мест, где за словами стоит
проверка; устройство каждой — в `NOTES.md`:

| Что стережёт | Код |
|---|---|
| Слот вне окна, дата в прошлом, второй пост в занятый день | `strategy._fit` |
| Голос бренда: отказ, а не предупреждение | `validators/check_voice.py` |
| Суфлёрный текст: цифры, длина строк, бюджет слов | `validators/check_script.py` |
| Макет: пути, фото, холст, чужие слова | `design.inspect` |
| Слоты макета: пустой и переполненный — отказ | `design._fill` |
| Потеря профиля при правке `core.md` | `refresh.review` |
| Механика с одним примером | `research.sift` |
| Дубль публикации | `posts.external_id UNIQUE` + статус `sending` до отправки |

## Следующий шаг

1. **Достать публикацию видео.** `publisher.collect` собирает только
   `{theme_id}-*.png`, поля под видео в `Package` нет вовсе, и текст
   поста обязателен — «В очередь» на рилсе упирается в «текста нет».
   Вторая цепь без этого не доходит до конца. Первый пункт важнее
   остальных.
2. **Пройти цепь целиком руками в Telegram**, от плана недели до
   комплекта. Стенд ходит по ролям поодиночке, живой человек — подряд, и
   стыки между ролями стенд не проверяет.
3. **Снять честный замер полной цепи через мост** —
   `MIGRATION_TO_CLAUDE_CODE.md`, этап 7.

Из ближнего: расписание сводки на понедельник (команда работает,
автозапуска нет) и внешняя проверка сценариев на пути моста (для плана,
текста и макета она есть).
