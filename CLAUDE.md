# Контент-завод — состояние проекта

Читается автоматически в начале каждой сессии. Держать актуальным **и
коротким**: всё, что здесь лежит, оплачивается контекстом на каждой
сессии, даже когда не нужно.

## Что это

Коробочный мультитенантный продукт: семь агентов-ботов в супергруппе
Telegram производят и публикуют контент по профилю бренда клиента.

Куда смотреть за подробностями:

| Вопрос | Файл |
|---|---|
| Как устроено целиком: два пути, мост, Director, субагенты | `ARCHITECTURE.md` |
| Почему подсистема сделана именно так, чем оплачено | `NOTES.md` |
| Что решено и не переоткрывается | `spec/README.md` (журнал решений) |
| Требования по ролям | `spec/`, восемь документов |
| Миграция на Claude Code, этапы и замеры | `MIGRATION_TO_CLAUDE_CODE.md` |

Спека не дублирует код: промпты в `roles/*.md`, схема базы в
`storage/db.py`, автоматическая приёмка в `tests/`. Копии промптов и
схемы из спеки убраны 16.08 — они разъехались с оригиналом и успели
соврать про две роли.

**`NOTES.md` не читается автоматически.** Берёшься за подсистему —
открываешь её раздел. Разделы: уроки проекта, порядок вызовов модели,
каркас роли, роли со структурным ответом, правка профиля, неуверенность
распаковки, сводка недели, проверка текста, сценарии роликов, дизайн,
монтаж, публикация, бренд.

## Как запустить

Завод стоит на автозапуске через `launchd`, агент
`space.lily.content-factory`. Поднимается при входе в систему и сам
перезапускает упавший процесс.

```bash
cd ~/code/content-factory && ./run.sh
```

`run.sh` видит загруженный агент и перезапускает **через него**. Запускать
`main.py` напрямую нельзя: launchd тут же поднимет свой, получится два
поллинга и взаимный `Conflict`. На этом уже спотыкались дважды.

Полезное:

```bash
launchctl print gui/$(id -u)/space.lily.content-factory | grep -E "state|pid"
launchctl kickstart -k gui/$(id -u)/space.lily.content-factory
launchctl bootout gui/$(id -u)/space.lily.content-factory   # снять автозапуск
```

Поставить заново или на другой машине — `./deploy/install-agent.sh`.

**Это агент, а не демон.** Стартует при входе в систему, не при загрузке
Мака. Демон работал бы от root без пользовательского окружения, и Chrome
для рендера макетов там не поднимется.

**Сон Мака останавливает завод.** Закрытая крышка это пауза: расписание и
публикация в это время не сработают.

Только **один** экземпляр: Telegram разрешает один опрос на бота, два
инстанса глушат друг друга (`Conflict: terminated by other getUpdates`).
Один процесс на Label гарантирует сам launchd.

**`SIGTERM` инстанс не берёт.** Застряв в цикле переподключения aiogram,
процесс не реагирует ни на `pkill -f`, ни на обычный `kill` — нужен `-9`.

Лог — `bot.log`.

## Что работает

- Автопровижининг десяти топиков при добавлении Ассистента админом
- Онбординг: маска → ссылки/файлы → распаковка → карточка ЯДРА →
  три спорных места → запись `core.md`
- Распаковка: `t.me/s/` без токенов, сайты, pdf/docx/txt/md,
  экспорт Telegram Desktop (`result.json`)
- Пересборка профиля файлом, ссылкой или словами, через подтверждение,
  с версией в git
- Ассистент отвечает моделью: профиль в контексте, состояние из БД
- Стратег строит план недели: слои → темы в БД → карточка с кнопками,
  выгрузка в `plans/ГГГГ-Wnn.md`
- Редактор пишет текст по теме: `idea` → `draft` → `ready`, текст в
  `posts/{id}.md`, путь в `themes.asset`
- Редактор Reels пишет суфлёрный текст: шесть блоков от модели, суфлёр
  собирает код, `posts/{id}-script.md` и разбор в `-script-notes.md`
- Дизайнер верстает макет по ТЗ площадки и рендерит PNG через headless
  Chrome, отдаёт и HTML, и PNG
- Монтаж собирает ролик из записи (Remotion, караоке-субтитры) и обложку
  вокруг лица через детектор macOS Vision; расслышанное неверно правится
  словарём бренда `montage/subtitles.md` — кнопкой «Правки» под роликом
  или руками, ролик пересобирается без новой расшифровки
- Публикатор собирает комплект, показывает превью и по кнопке публикует
  в Telegram-канал, пишет факт в `posts`
- Ресёрчер снимает свою статистику с `t.me/s/` и собирает недельную
  сводку, выгрузка в `research/ГГГГ-Wnn.md`
- Профиль нарезается кодом в `research/profile-digest.md`, кэш по `stat()`
- Мост: `bridge.snapshot` кладёт Ресёрчеру готовые цифры в
  `tasks/{id}/stats.md`; `bridge.harvest` сажает план через
  `strategy.land`, текст через `editor.land`, макет через `design.land`

## Чего нет

Шаги онбординга O4–O15 (референсы, фото, цифры, оформление), поэтому нет
`goals.md`, `sources.md`, дизайн-токенов. Стратег из-за этого работает на
запасной пропорции 60/20/20 и говорит об этом в «Контексте недели».

`platforms.md` **заведён** 31.08 руками, минуя онбординг: Telegram семь
раз в неделю, Instagram три reels и две карусели. Частота теперь правило
бренда, а не предложение модели.

Метрик по факту публикации нет: снимки через 24 часа, 72 часа и 7 дней
не снимаются. Своя статистика считается по публичной ленте канала целиком,
без привязки к слоту плана.

Модель зовут из восьми мест: `unpack.py`, `refresh.py`, `research.py`,
`reply.py`, `strategy.py`, `editor.py`, `reels.py`, `design.py`.
Все восемь — **старый путь**, через `agent.ask`. Мост в Claude Code сюда
не входит: там модель зовёт Claude Code, и `config.py` на это не влияет
ничем. Граница решена 30.08, см. раздел 12 миграции.

Мёртвых настроек в `.env` четыре, и все — старого пути:
`MODEL_PUBLISHER`, `EFFORT_PUBLISHER` (Публикатор модель не зовёт вовсе),
`MODEL_IDEATOR`, `EFFORT_IDEATOR` (ключи в `config.py`, в `.env` их нет).
Снимаются на этапе 8 вместе с остальным старым слоем.

**Бот Идеатора поднят и поллится, а поведения у него нет** — ни
хендлера, ни топика, ни вызова модели. `BOT_IDEATOR` в `.env` настоящий,
`main.py` берёт в воркеры всех, кроме Ассистента. Не путать
`tokens["ideator"]` (живой) с `role_models` и `role_effort` (мёртвые).

## Правила, которые легко нарушить

**`callback_query` приходит боту, который отправил сообщение.** Поэтому
рабочие боты тоже поллятся, но только на нажатия.

**У General нет `message_thread_id`** — в базе `NULL`, при отправке
параметр не передаётся вовсе.

**Инлайн-кнопка `web_app` работает только в личке.** Дашборд в группе —
только Direct Link Mini App через `/newapp`.

**Потолок сообщения 4096 знаков, а подписи под картинкой 1024.**
`registry.say` режет по абзацам, `collect()` считает потолок по наличию
картинки.

**На Opus 5 нет `temperature`** (400) и **мышление включено по
умолчанию** — `max_tokens` считает мышление вместе с ответом.

**Slug бренда не меняется никогда** — на нём завязаны пути к артефактам.

**`git` ищет репозиторий вверх по дереву.** Папка бренда без своего
`.git` находит первый попавшийся выше, и `add -A` уносит туда всё
подряд. `brand._own_repo` сверяет `--show-toplevel` с самой папкой бренда.

**Порядок блоков в системном промпте ломать нельзя** — кеш это совпадение
префикса. Устройство — `NOTES.md`, «Порядок вызовов модели».

## Где границу держит код

Промпт это просьба, а не гарантия. Восемь мест, где за словами стоит
проверка; устройство каждой — в `NOTES.md`:

| Что стережёт | Код |
|---|---|
| Слот вне окна, дата в прошлом, второй пост в занятый день | `strategy._fit` |
| Голос бренда: отказ, а не предупреждение | `validators/check_voice.py` |
| Суфлёрный текст: цифры, длина строк, бюджет слов | `validators/check_script.py` |
| Макет: пути, фото, холст, чужие слова | `design.inspect` |
| Слоты макета: пустой и переполненный — отказ | `design._fill` |
| Потеря профиля при правке `core.md` | `refresh.review` |
| Механика с одним примером | `research.sift` |
| Дубль публикации | `posts.external_id UNIQUE` + статус `sending` до отправки |

## Следующий шаг

Первый пункт важнее остальных.

1. **Довести публикацию до конца в живую.** Ни одного поста завод ещё не
   опубликовал: в `posts` пусто. Пока это не произошло, цепь замкнута
   только на стенде. Тема в статусе `ready` уже лежит.
2. **Пройти цепь целиком руками в Telegram** — от плана недели до
   комплекта. Стенд ходит по ролям поодиночке, живой человек — подряд, и
   стыки между ролями стенд не проверяет.
3. **Пройти честный замер полной цепи через мост** — раздел 14 миграции.

Осталось из ближнего:

- **расписание сводки на понедельник** — команда `напиши дайджест недели`
  работает, автозапуска нет;
- **внешняя проверка текстов и макетов на пути моста.** Для плана она
  есть, для остального нет.

Дальше метрики: Ресёрчер снимает их через 24 часа, 72 часа и 7 дней.
Без них Стратег навсегда останется без слоя «своя статистика», порог
авто-режима (десять утверждений подряд) нечем считать, а Идеатор считает
ставку по охвату оценкой, а не измерением.

**Идеатор из связки плана убран 31.08.** Цепь плана это
`researcher → strategist`, и всё. Он был самым дорогим шагом (395 с в
`plan-06`), а план без раскачки остаётся рабочим — только `variants` у
тем остаются пустыми, и это называется человеку строкой. По просьбе
«раскачай тему N» он зовётся отдельно.

## Миграция на Claude Code

Отдельная ветка — `MIGRATION_TO_CLAUDE_CODE.md`, этапы 1–6 пройдены:
мост собран (`orchestrator/bridge.py`, команды `/plan`, `/post`,
`/reels`, `/research`, `/design`, `/idea`) и прошёл живьём 30.08.

Честный замер полной цепи снят 30.08: задача `2026-08-30-plan-06`,
**1223 с**, три роли подряд и все синхронно — Ресёрчер (454 с), Стратег
(256 с), Идеатор (395 с). Потолок в 1800 с держит с запасом. Оценка CLI
по API-тарифу $4.71 — это оценка, а не списание.

Денег этот путь не тратит: подпроцесс идёт **без** `ANTHROPIC_API_KEY`,
авторизуется входом CLI по подписке, расходуются лимиты, а не баланс.

Вход в мост с 30.08 не только команда: обычная просьба словами уходит
туда же — `bots/router.py` распознаёт, что попросили, `handlers.AS_WORKFLOW`
переводит это в workflow, а кого звать, решает Director. Старый путь не
переписан и поднимается явным упоминанием бота роли; Публикатор в мост
не уходит вовсе.

Про модель решено 30.08: `.claude/settings.json` закрепляет
`claude-opus-5` и усилие `medium`. Python в этот выбор не вмешивается —
`clean_env` не пропускает ни `ANTHROPIC_MODEL`, ни `MODEL_*`.

Следующий этап 7: гонять один workflow параллельно со старым путём.
