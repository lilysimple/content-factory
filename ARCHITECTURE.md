# Архитектура контент-завода

Итоговая картина на 30 августа 2026. Что есть сегодня, что куда идёт и
где границы, которые нельзя двигать.

Состояние проекта — `CLAUDE.md`. Почему подсистема сделана именно так и
чем это оплачено — `NOTES.md`. История и замеры миграции —
`MIGRATION_TO_CLAUDE_CODE.md`. Закрытые решения — `spec/README.md`.
Этот файл описывает **устройство**, а не состояние: если он разойдётся с
кодом, прав код.

## 1. Два пути, и оба живые

```text
                    ┌──────────────────────────────┐
                    │   Супергруппа Telegram        │
                    │   восемь ботов, десять топиков│
                    └───────────┬──────────────────┘
                                │
                 ┌──────────────┴───────────────┐
                 │                              │
     СТАРЫЙ ПУТЬ │                              │ НОВЫЙ ПУТЬ
     (работает)  │                              │ (шесть команд)
                 ▼                              ▼
        orchestrator/agent.py           orchestrator/bridge.py
        cfg.model_for(role)             claude -p, чистое окружение
                 │                              │
                 ▼                              ▼
        Anthropic API                   Claude Code (подписка)
        ключ из .env                    вход CLI из Keychain
        claude-opus-5                   claude-opus-5, effort medium
                 │                              │
                 ▼                              ▼
        шесть ролей в Python            Director → субагенты
```

Пути не заменяют друг друга и не мешают: мост висит на отдельных
командах, всё остальное идёт как шло. Сравнивать результаты можно только
так — и только на одинаковой модели, поэтому она закреплена.

**Публикация вне обоих.** `orchestrator/publisher.py` модель не зовёт
вовсе и работает при пустом балансе: собрать комплект, проверить потолки
и отправить — детерминированная работа.

## 2. Мост: что он знает и чего не должен знать

`orchestrator/bridge.py`. Ответственность ровно одна — довезти задачу до
Director и вернуть результат.

```text
человек: /post 2026-08-17-telegram-01
    │
    ├─ create_task ─── tasks/{id}/input.md   ← контракт Python → Director
    │                  строка в bridge_runs
    │
    ├─ run ─────────── claude -p, cwd=корень, env=белый список
    │                  ждёт до TIMEOUT=1800 с
    │
    └─ читает ──────── tasks/{id}/final.md   ← контракт Director → Python
                       for_telegram() → в чат
```

**Мост знает четыре вещи:** как завести папку задачи, как запустить
процесс, как дождаться, как прочитать `final.md`.

**Чего в нём нет и не должно появиться:** выбора субагентов, порядка
вызова, промптов ролей, сборки результатов. Как только сюда переедет хоть
одно, решение «кого звать» размажется между `bots/` и `.claude/`, и к
третьей правке никто не скажет, где на самом деле выбирается workflow.

### Окружение подпроцесса — белый список

`KEEP = PATH, HOME, USER, LANG, LC_ALL, TMPDIR, SHELL`

`config.py` зовёт `load_dotenv()`, поэтому в окружении процесса бота лежат
ключ API и токены восьми ботов. Наследование отдало бы их наружу. Плюс
`ANTHROPIC_API_KEY` увёл бы вызов на API-тариф, а новый путь идёт по
подписке.

### Точки входа

| Команда | Что просит человек | Что кладётся в `input.md` |
|---|---|---|
| `/plan` | контент-план на неделю | свободные слоты |
| `/post` | текст поста по теме | таблица незакрытых тем |
| `/reels` | сценарий ролика | таблица незакрытых тем |
| `/design` | макет по готовому тексту | таблица незакрытых тем |
| `/idea` | раскачать тему до заходов | таблица незакрытых тем |
| `/research` | сводка недели | ничего, он ходит наружу |

`WORKFLOWS` описывает **просьбу**, а не роли. Шаблон команд строится из
его ключей, чтобы два списка не разъехались.

## 3. Director и субагенты

```text
Director (.claude/CLAUDE.md)
   │  читает input.md, выбирает МИНИМАЛЬНЫЙ workflow
   │
   ├─ researcher   → research.md    факты, механики, статистика
   ├─ strategist   → strategy.md    скелет: слот, рубрика, цель, воронка
   ├─ ideator      → ideas.md       заходы, спор Продюсер/Скептик, вердикт
   ├─ writer       → final.md       текст в голосе бренда
   ├─ reels        → script.md      суфлёрный текст, шесть блоков
   └─ designer     → design.md      макет по ТЗ площадки, HTML + PNG
   │
   └─ собирает → status.json, final.md
```

**Субагентов зовут синхронно.** `run_in_background: false`, каждый раз
руками — у инструмента `Agent` фон включён по умолчанию. В `claude -p`
конец хода это конец процесса: фоновый субагент умирает вместе с ним.
Оплачено прогоном `plan-03` — 275 секунд, ноль артефактов, человек в чате
получил отказ.

**Ход не заканчивается, пока не написан `final.md`.** Нет результата —
пиши в `final.md`, что не сошлось. Ход, законченный обещанием вернуться,
для человека неотличим от поломки, потому что возвращаться будет некому.

### Промпт роли живёт в одном месте

```text
.claude/agents/{роль}.md     адаптер: кто ты, откуда вход, куда выход,
                             какой код тебя проверит
roles/{роль}.md              поведение роли — читается субагентом на старте
```

Копии промптов в этом проекте уже разъезжались с оригиналом и успели
соврать про две роли. У поведения роли один дом.

**Director сам эти файлы не читает.** Субагент читает их на старте; чтение
Director-ом оплачивает второй экземпляр в его контексте.

## 4. Модель и рантайм: кто решает

| | Старый путь | Новый путь |
|---|---|---|
| Кто выбирает | Python, `config.py` | Claude Code |
| Где задано | `ANTHROPIC_MODEL`, `MODEL_*`, `EFFORT_*` | `.claude/settings.json` |
| Сегодня | `claude-opus-5`, усилие `high` | `claude-opus-5`, усилие `medium` |
| На роль | `cfg.model_for(role)` | `model`/`effort` во frontmatter адаптера |
| Оплата | баланс API | лимиты подписки |

**Python на модель нового пути не влияет ничем.** Ни `--model` флагом, ни
переменной окружения: `clean_env` их не пропускает, и это граница, а не
недоделка. Пин живёт в `.claude/settings.json` — в репозитории, под
версией, поэтому модель перестала быть умолчанием CLI, которое может
смениться между прогонами и не оставить следа.

Мёртвые ключи старого пути, снимаются на этапе 8: `MODEL_PUBLISHER` и
`EFFORT_PUBLISHER` (Публикатор модель не зовёт), `MODEL_IDEATOR` и
`EFFORT_IDEATOR` (в Python роли Идеатора нет).

## 5. Границу держит код, а не промпт

Самый дорогой урок проекта. Промпт это просьба; проверяет код.

| Что проверяется | Чем | Оплачено |
|---|---|---|
| Слот из списка свободных | `strategy._fit` | дата вне окна, дата из прошлого, «как-нибудь на неделе» |
| Окно и занятость — один дом | `strategy.free_slots` | Director считал сам, запросом мимо модуля |
| Голос текста | `validators/check_voice.py` — **отказ**, не предупреждение | — |
| Суфлёрный текст | `validators/check_script.py` | цифры вместо слов, строки не под вдох |
| Макет | `design.inspect()` | абсолютные пути, несуществующее фото |
| Дубль публикации | `posts.external_id UNIQUE` + статус `sending` до отправки | — |
| Разметка в чат | `bridge.for_telegram` | голая скобка роняла отправку удавшейся задачи |
| Правка профиля | `refresh.review` | одна правка стирала работу онбординга |

Субагенты прогоняют валидаторы на себе для быстрой обратной связи. **Это
не заменяет внешнюю проверку** — Python не верит их слову.

## 6. Где живёт состояние

```text
factory.db            темы, публикации, тенанты, журнал прогонов моста
  themes              источник правды по плану
  posts               факт публикации, external_id UNIQUE
  bridge_runs         прогоны моста: время, оценка, исход, session_id

~/code/content-factory-brands/{slug}/     профиль клиента, наружу не пушится
  core.md             ЯДРО — профиль бренда
  design/             токены, ТЗ площадок, фото
  research/           sources.md и недельные сводки
  plans/, posts/      выгрузки

tasks/{id}/           артефакты прогона моста, в .gitignore
```

**Известный разрыв.** Новый путь в базу и папку бренда ничего не
возвращает: всё, что собирают субагенты, ложится только в `tasks/{id}/`.
План, собранный через мост, следующий прогон не увидит — слоты останутся
свободными. Это и есть приёмка этапа 7: результат должен доходить до базы.

## 7. Что в мост не переносится

| Что | Почему |
|---|---|
| `publisher.py` | Не AI-роль вовсе. Проверить потолки и отправить — детерминированно, и работает при пустом балансе |
| `reply.py` | Разговор, а не задача с началом и концом |
| `unpack.py`, `refresh.py` | Мастер с кнопками и подтверждениями, а не одна просьба |

Поэтому ключ API сегодня несущий: шесть команд покрывают пять точек
вызова модели из восьми. Отзыв ключа — последний шаг этапа 8, а не первый.

## 8. Где мы на маршруте

```text
1-6  ✅  аудит, структура, промпты, ручная проверка, мост, живые прогоны
 7   ▶   честный baseline полной цепи и возврат результата в базу
 8   ○   снимать старый слой по одной роли, стенд как приёмка
```

Ближайшее — раздел 14 миграции: замер цепи `researcher → strategist →
ideator` без переиспользования артефактов, на закреплённой модели.
Главный вопрос замера не «как сократить сообщения», а **оправдывает ли
качество результата стоимость и время трёх независимых субагентов.**

## 9. Шесть правил, каждое оплачено поломкой

Переносятся на любую роль и на обе архитектуры.

1. **Промпт это просьба, границу держит код.**
2. **Состояние приходит из данных, а не из вшитой фразы.** Устаревшее
   утверждение о состоянии переживает то состояние, которое описывало.
3. **Роли нужен способ сказать «не сошлось».** `gaps`, `unmet`, `notes`.
4. **Молчание неотличимо от поломки.**
5. **Сломанное выглядит рабочим.** Chrome пишет PNG и не выходит; шрифты
   не успевают доехать, и макет молча уходит системным.
6. **У каждого поля должен быть потребитель.** Промпт требовал
   `confidence`, а читать его было некому.
