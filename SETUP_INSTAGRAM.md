# Автопостинг в Instagram: что нужно сделать руками

Код готов и проверен стендом (цикл 31). Не хватает трёх вещей, и все три
живут в вашем аккаунте, а не в репозитории: приложение Meta, права и
токен. Это полчаса, один раз.

Устройство и причины решений — `NOTES.md`, «Instagram: вторая площадка».

## Коротко

| | Что получаем | Куда положить |
|---|---|---|
| 1 | Аккаунт Instagram в режиме Business, связанный со страницей Facebook | — |
| 2 | Приложение в Meta for Developers с правами на публикацию | — |
| 3 | `IG_USER_ID` — числовой id аккаунта Instagram | `.env` |
| 4 | `IG_TOKEN` — токен страницы, он же не истекает | `.env` |

Ревью приложения **не нужно**: Meta отдаёт Standard Access тем, кто
публикует в аккаунты своего же владельца. Ревью понадобится, когда завод
начнёт публиковать за клиентов.

## 1. Аккаунт и страница

Ролик — основной формат, а ролик уходит байтами только на фейсбучном
пути. Он требует, чтобы `lily_.space` был **Business-аккаунтом,
связанным со страницей Facebook**.

- Instagram → Настройки → Тип аккаунта → переключить на Business, если
  стоит Creator или личный.
- Там же → Связанные аккаунты → привязать страницу Facebook. Страницы
  нет — создать пустую, она нужна только как держатель прав; постить в
  неё завод не будет.

Страницы нет и делать её не хочется — есть второй путь: `IG_LOGIN=instagram`
работает без страницы, но ролик там берётся по публичной ссылке, а
ссылку завод даёт через Telegram с потолком 20 МБ. Смонтированные ролики
весят 14–275 МБ, то есть карусель на этом пути пойдёт, а ролики почти
никогда. Выбор за вами, дом по умолчанию фейсбучный.

## 2. Приложение Meta

1. [developers.facebook.com/apps](https://developers.facebook.com/apps) →
   Create App → тип **Business**.
2. В приложении: Add Product → **Instagram** → Instagram Graph API.
3. App Roles: убедиться, что вы администратор. Режим приложения —
   Development, этого достаточно для своего аккаунта.
4. Права, которые понадобятся в Graph API Explorer:
   `instagram_basic`, `instagram_content_publish`,
   `pages_read_engagement`, `pages_show_list`.

## 3. `IG_USER_ID`

В [Graph API Explorer](https://developers.facebook.com/tools/explorer):

1. Выбрать своё приложение, нажать Generate Access Token, выдать права из
   списка выше.
2. Запрос `me/accounts` — вернёт страницы. Взять `id` нужной страницы.
3. Запрос `{id страницы}?fields=instagram_business_account` — вернёт
   числовой id аккаунта Instagram вида `1784140…`.

Это и есть `IG_USER_ID`. Он не меняется.

## 4. `IG_TOKEN`, который не истекает

Токен из Explorer живёт час — для проверки годится, для завода нет.
Нужен **токен страницы, выведенный из долгого токена пользователя**:
такой не истекает вовсе.

1. Короткий токен пользователя из Explorer скопировать.
2. Обменять на долгий (60 дней):

```
GET https://graph.facebook.com/oauth/access_token
  ?grant_type=fb_exchange_token
  &client_id={APP_ID}
  &client_secret={APP_SECRET}
  &fb_exchange_token={короткий токен}
```

3. Этим долгим токеном спросить токен страницы:

```
GET https://graph.facebook.com/me/accounts?access_token={долгий токен}
```

В ответе у каждой страницы есть `access_token` — вот он и нужен. Он
живёт, пока не сменится пароль и не снимутся права.

Проверить, что токен не истекает, можно в
[Access Token Debugger](https://developers.facebook.com/tools/debug/accesstoken/):
в поле Expires должно стоять «Never».

## 5. Положить в `.env`

```
IG_LOGIN=facebook
IG_USER_ID=17841400000000000
IG_TOKEN=EAAG...
```

Перезапустить завод:

```bash
launchctl kickstart -k gui/$(id -u)/space.lily.content-factory
```

Проверить, что завод увидел аккаунт:

```bash
./.venv/bin/python -c "
from orchestrator import instapost, strategy
from storage import db; from config import cfg
db.init(cfg.db_path)
print('путь:', instapost.login(), instapost.host_api())
print('готов:', instapost.ready())
print('автомат:', strategy.auto_publish())"
```

Должно напечатать `готов: True` и `instagram` в наборе автомата.
Остаток суточного лимита спросить у Meta:

```bash
./.venv/bin/python -c "
import asyncio
from orchestrator import instapost
from storage import db; from config import cfg
db.init(cfg.db_path)
print('осталось публикаций:', asyncio.run(instapost.left_today()))"
```

Эта команда — первая настоящая проверка прав: она ходит в Meta. Отказ она
печатает текстом Meta, а не своими словами.

## 6. Первый ролик

**Публикация идёт в живой аккаунт с подписчиками.** Первый раз пройдите
цепь кнопками и посмотрите на результат, прежде чем включать автомат.

1. Прислать дубль в 🎬 Reels — монтаж соберёт ролик.
2. Под карточкой монтажа:
   - **📤 В очередь** — публикует сейчас, через превью и кнопку;
   - **📅 В свой день** — занимает ближайший свободный день Instagram, и
     тогда ролик выходит сам, когда включён автомат.
3. В превью проверить подпись и первый кадр. Кнопка «📤 Опубликовать»
   появляется только если комплект прошёл потолки площадки.

## 7. Автомат по времени

Включается не раньше порога: десять утверждений и две недели с первой
публикации, держит их `publisher.gate`, а не промпт.

```
/auto            # что мешает включению и сколько набрано
/auto on
/auto 10:30      # время слота в вашем поясе
```

Автомат берёт только темы с **наступившей датой**. Ролик без дня он не
увидит — для этого и есть кнопка «В свой день».

## Что останется несделанным

- **Метрик по факту публикации нет.** Снимки через 24 часа, 72 часа и
  7 дней не снимаются ни в Telegram, ни в Instagram.
- **Сторис завод не публикует.** Формат в `platforms.md` заявлен, слотов
  под него план не ставит, и транспорт его не умеет.
- **Живой публикации в Instagram ещё не было ни одной.** Стенд проверяет
  швы на поддельном Graph API; первый настоящий пост — ваш.
